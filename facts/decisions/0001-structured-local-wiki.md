# ADR 0001：规则数据与阅读入口分离

状态：采用。依据用户本轮明确指定的三源合并目标。

## 背景

规则正文、角色表、模组表与剧本分散在多份来源中。只生成一份巨大的 HTML 会让规则本身难以复用；只保留来源目录又会把查找、去重和冲突处理留给读者。

## 决定

- `index.html` 与 `assets/` 只负责显示；`data/<类别>/*.json` 是结构化条目，`text/<类别>/*.txt` 保存长正文。
- 规则实体按类别及作用域确定稳定 ID。同名身份、事件或规则在不同模组中分别存在；已证实别名映射到同一角色。
- 原文候选、字段采纳来源与差异均保留，优先级固定为 wiki > lloyd > ricardo；原件及历史目录名只用于追溯，不是读者导航层级。
- 字段中的“明确空白／无”与整个页面缺少正文分开处理。来源空页不会删除次级资料。
- 自动提取不推断缺失规则；不确定的内容保留原始表格和正文，并通过核对完善。
- Wiki 目录清单作为采集分母；图像、附件、特殊命名空间分别核验，不能用文章计数替代媒体完整性。
- 阅读器使用本地静态 HTTP 服务，不引入运行引擎、数据库或在线后端。

## 取舍

JSON 与正文分离增加了生成、索引和路径校验工作，但允许后续工具直接使用同一份规则资料。保留原始快照占用额外空间，换来可复核的来源与重建能力。读者可浏览统一条目；需要审阅来源时再展开候选和出处。

## 验证

生成器及核验器在 `tools/`。采集覆盖、来源优先级、路径与浏览器呈现已核验，见 [交付核对](completion-audit.md)。原站缺失状态和人工阅读验收边界在该记录中说明。
