# 重要误解记录

状态：持续维护  
最近更新：2026-06-22

这个文件记录开发中已经暴露过的规则或产品理解误区。后续遇到相似问题时，先查这里。

## 主人公人数不决定行动牌数量

误解：第一版曾把主人公行动次数写成 `protagonistCount`，导致 1 名主人公时每回合只能暗置 1 张行动牌。

更正：主人公方每回合总是暗置 3 张行动牌。1-3 名玩家只是共同扮演主人公方；线上版以后需要考虑“由谁负责哪张牌”或“队长如何确认行动”，但这不改变主人公方每回合 3 张行动牌的规则。

实现要求：

- `actionLimit(state, SIDES.PROTAGONIST)` 必须返回 3。
- UI 可以后续增加行动分派，但不能减少主人公方行动总数。

## UI 过滤不能代替核心校验

误解风险：只在 UI 中隐藏非法选项，就以为规则安全。

更正：UI 应展示合法选项，减少误操作；规则核心仍必须拒绝非法命令。未来联机时客户端请求不可信，服务端必须重新验证。

当前要求：

- 死亡角色不能成为行动牌目标。
- 同一阵营不能在同一角色或版图重复放置行动牌。
- 已使用过能力的角色不能再次出现在能力候选中。

## 公开剧本信息和非公开剧本信息必须分开

误解风险：为了调试方便，把采用规则、事件当事人、角色身份直接显示给所有视图。

更正：可以在开发者同屏界面同时展示剧作家视图和主人公视图，但数据投影必须区分：

- 剧作家视图显示 closed script。
- 主人公视图只显示 open script 与已公开信息。

后续联机版必须由服务端分别发送投影，不能让主人公客户端收到完整 closed script 后再本地隐藏。

## 友好能力不是隐藏身份能力

误解风险：因为身份能力需要隐藏，连角色卡上的友好能力、友好门槛和公开特性也一起藏起来。

更正：角色卡上的公开信息双方都应该可见，包括不安限度、友好限度、友好能力、禁行区域等。隐藏的是角色被分配到的身份，以及由身份带来的能力和失败条件。

实现要求：

- `CharacterState` / 静态角色定义应包含 `goodwillLimit` 和 `skills`。
- `projectView` 不应在主人公视图中移除公开友好能力。
- 卡面显示友好指示物时应显示为当前值 / 友好限度。

## 好感度高时不是多选一

误解风险：一个角色有多个已解锁技能时，让玩家从中选择一个发动。

更正：达到较高好感度后，低门槛技能也同时解锁。每天发动技能时，所有已经解锁且满足使用条件的技能都可以发动。标注每轮限一次的技能跨天共享轮回内使用次数；没有该标注的技能默认每天可发动一次。

实现要求：

- `skills` 每项需要独立记录 `requiredGoodwill` 和 `frequency`。
- 状态机后续应分别追踪每日技能使用和每轮技能使用。
- UI 不应把多个技能呈现为互斥选项。

## 主人公行动牌不是共享手牌

误解风险：把主人公方做成一副共享手牌，导致每轮限 1 次的行动牌全队只能使用 1 张。

更正：主人公方每名玩家各有一副行动牌。当前原型即使由一个人操作，也要以绿、红、蓝三副牌建模。每副牌独立追踪本轮弃牌，因此绿、红、蓝三张 `友好 +2` 都还没使用时，同一回合可以分别从三副牌中打出。

实现要求：

- 主人公行动阶段的 3 次行动分别绑定到绿、红、蓝行动牌。
- 每轮限 1 次的主人公行动牌必须按 `deckId` 追踪；目前确认包括 `友好 +2`、`不安 -1`、`禁止移动`。
- 剧作家和主人公视图都应展示本轮弃牌堆，并用颜色标记主人公弃牌来源。

## 同名移动牌不会互相抵消

误解：把移动结算实现成坐标异或，导致两张同名 `移动上下` 或 `移动左右` 互相抵消。

更正：同名移动牌重叠时只按该方向正常移动 1 次，不移动两次，也不抵消。不同方向按纸质规则合成：上下加左右为斜向，上下加斜向为左右，左右加斜向为上下。

实现要求：

- 移动结算应按出现过的移动牌名集合合成，不按同方向出现次数奇偶抵消。
- `禁止移动` 仍优先取消目标上的所有移动类行动牌。

## First Steps 没有最终决战

误解：所有惨剧模组在最后一轮失败后都会进入最终决战。

更正：主人公之书校对稿说明 First Steps 取消最终决战；主人公在所有轮回中都失败时，直接判定剧作家胜利。其它模组仍按通常流程，在最后一轮失败后进入最终决战。

实现要求：

- 剧本数据需要能表达是否启用最终决战。
- First Steps 的最后一轮失败应进入 `finished` 并设置剧作家胜利。
- 允许最终决战的剧本进入最终决战前，应先把盘面复原到轮回开始状态。

## 主人公能力候选不按效果是否会改变状态过滤

误解风险：如果目标身上没有不安，就把“移除不安”的能力从可发动列表中移除；或者因为角色身份可能/必定无视友好，就把该角色的友好能力从主人公候选列表中移除。

更正：主人公能力列表只检查友好是否达到门槛、能力是否未用过，以及是否存在结构性可选对象。对象身上是否真的有可移除的指示物、角色身份是否会拒绝友好能力，都属于宣告之后的审批或结算结果，不属于候选过滤条件。

无视友好尤其不能提前过滤。即使医生等角色的身份具有无视友好或强制无视友好，主人公方仍然可以发起使用能力的动作；后续由剧作家选择拒绝，或因强制无视友好自动拒绝。这个过程本身会向主人公提供身份推理信息。

实现要求：

- 可发动能力列表：友好达到门槛 + 能力未用过 + 存在结构性可选对象。
- 结算可以产生“没有变化”的日志。
- 需要剧作家确认是否无视友好的能力必须逐项审批，不能批量提交后统一审批。
- 强制无视友好的角色也必须先允许宣告，再自动拒绝并记录原因。
