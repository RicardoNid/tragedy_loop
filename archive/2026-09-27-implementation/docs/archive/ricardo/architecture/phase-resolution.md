# 阶段与结算规则

状态：草案  
最近更新：2026-06-22

本文描述当前 Web 原型状态机已经实现的阶段、允许命令和结算规则。它记录的是程序现状，不等同于完整纸质版规则。

核心实现位置：`code/web/core/engine.mjs`

## 总览

当前一日流程为：

```text
dawn
-> mastermind_action
-> protagonist_action
-> action_resolution
-> mastermind_ability
-> protagonist_ability
-> incident
-> leader_rotation
-> end_of_day
-> next_day / loop_end / final_guess / finished
```

`pendingDecision` 会暂停阶段推进。当前只有主人公能力审批会设置 `pendingDecision`；存在待审批能力时，不能暗置行动牌，也不能推进阶段。

## `dawn` - 回合开始阶段

允许命令：

- `advancePhase(state)`

当前规则：

- 这是纸质版一天流程中的第 I 阶段。
- 当前第一版原型尚未实现任何回合开始效果，因此本阶段只记录阶段位置并允许推进到 `mastermind_action`。
- 新游戏、新一天和新轮回都会先进入 `dawn`。

## `mastermind_action` - 剧作家行动阶段

允许命令：

- `placeAction(state, { side: mastermind, cardId, targetType, targetId })`
- `advancePhase(state)`

暗置规则：

- 剧作家必须暗置 3 张行动牌。
- 行动牌必须属于剧作家手牌。
- 行动牌必须允许放置到目标类型。
- 角色目标必须存在且仍然生存。
- 版图目标必须存在。
- 同一阵营不能在同一角色或版图上重复放置行动牌。
- 每轮限 1 次的行动牌如果已进入本轮弃牌堆，不能再次暗置。

推进规则：

- `advancePhase` 会检查剧作家已暗置数量必须正好为 3。
- 检查通过后进入 `protagonist_action`。
- 本阶段不揭示行动牌，也不结算行动牌效果。

## `protagonist_action` - 主人公行动阶段

允许命令：

- `placeAction(state, { side: protagonist, deckId, cardId, targetType, targetId })`
- `advancePhase(state)`

暗置规则：

- 主人公方总共暗置 3 张行动牌，玩家人数不改变这个数量。
- 当前原型把主人公行动牌建模为绿、红、蓝三副牌。
- 每副牌每阶段最多暗置 1 张。
- UI 按绿、红、蓝固定顺序要求主人公暗置；主人公只选择行动牌和对象，不手动选择颜色。
- 行动牌必须属于主人公手牌。
- 每轮限 1 次的行动牌按 `deckId` 分别追踪弃牌。
- 因此绿、红、蓝三副牌的 `友好 +2` 若都尚未进入弃牌堆，同一回合可以打出三张 `友好 +2`。
- 其余目标合法性与剧作家行动阶段一致：角色必须生存，版图必须存在，同一阵营不能重复放置到同一目标。

推进规则：

- `advancePhase` 会检查主人公已暗置数量必须正好为 3。
- 检查通过后进入 `action_resolution`。
- 进入 `action_resolution` 时，双方行动牌会公开揭示，但尚未执行移动和指示物结算。

## `action_resolution` - 行动结算阶段

允许命令：

- `advancePhase(state)`

触发时机：

- 从 `protagonist_action` 推进时进入本阶段，并公开揭示双方行动牌。
- 在本阶段再次推进时，执行行动牌结算。

结算顺序：

1. 每轮限 1 次的行动牌进入本轮弃牌堆。
2. 先结算移动类行动牌。
3. 再结算指示物类行动牌。
4. 清空 `placedActions`。
5. 若游戏仍为进行中，进入 `mastermind_ability`。

移动结算：

- 只处理目标为角色、效果为 `move` 或 `forbid_movement` 的行动牌。
- 如果目标角色已死亡，移动不结算。
- 若同一目标上存在禁止移动，所有移动不结算。
- 移动方向按“出现过哪些移动牌名”合成，而不是按同方向奇偶抵消：
  - `移动上下` + `移动左右` => 斜向移动。
  - `移动上下` + `斜向移动` => 左右移动。
  - `移动左右` + `斜向移动` => 上下移动。
  - 同名移动牌重叠时按该方向移动 1 次，不移动两次，也不抵消。
- 若三个方向同时出现，当前原型记录为移动方向互相抵消；该情形仍需后续资料确认。
- 若目标区域是角色禁行区域，角色停留原地。
- 否则角色移动到目标区域并记录日志。

指示物结算：

- 处理非移动、非禁止移动的行动牌。
- 按同一目标分组，再分别处理 `goodwill`、`paranoia`、`intrigue`。
- 若同一目标同一指示物同时存在禁止类牌和增减类牌，则该指示物变化被禁止。
- 例外：若同一行动结算中有 2 张或以上 `禁止密谋`，所有 `禁止密谋` 均不生效。
- 同一目标同一指示物的正数变化合计后结算；负数变化合计后结算。
- 指示物不会降到 0 以下。
- 如果实际变化量为 0，记录“没有变化”的日志。

当前限制：

- 复杂的同时结算优先级仍是第一版简化。
- 尚未实现需要中途选择目标的复杂结算队列。

## 暗置行动牌的公开信息

行动牌在揭示前仍隐藏牌名，但放置目标是公开信息：

- 公共日志会记录某方在某角色或版图上暗置行动牌。
- 对方投影视图中的 `placedActions` 会把 `cardId` 改为 `hidden`，但保留 `targetType` 和 `targetId`。
- 棋盘上会在目标角色或版图显示暗置标记。
- 主人公暗置标记使用对应牌堆颜色：绿、红、蓝。
- 剧作家暗置标记使用紫色。
- 进入 `action_resolution` 后，投影视图会向双方公开所有行动牌牌名。

## `mastermind_ability` - 剧作家能力阶段

允许命令：

- `useMastermindAbility(state, { actorId, targetType, targetId })`
- `advancePhase(state)`

候选过滤：

- 当前阶段必须是 `mastermind_ability`。
- 角色必须生存。
- 角色本日尚未使用过剧作家能力。
- 当前实现的剧作家阶段能力项包括“主谋”“传谣人”，以及医生在友好达到该技能门槛且身份具有无视友好/强制无视友好特性时可由剧作家使用的医生友好能力。
- 角色必须存在至少 1 个可发动能力项和合法目标。
- 当前原型仍按角色追踪本日剧作家能力使用记录：同一角色发动过 1 个剧作家能力项后，本日不再显示该角色的其它剧作家能力项。

主谋能力：

- 可选择同区域生存角色，或主谋所在版图。
- 角色目标必须与主谋同区域。
- 版图目标必须是主谋所在区域。
- 效果：目标增加 1 枚密谋。
- 使用后该角色加入本日已使用能力列表。

传谣人能力：

- 可选择同区域生存角色。
- 可以选择传谣人自己。
- 效果：目标增加 1 枚不安。
- 使用后该角色加入本日已使用能力列表。

医生例外能力：

- 条件：医生友好达到 2 枚或以上，且医生的身份具有“无视友好”或“强制无视友好”特性。
- 可选择同区域另一名生存角色。
- 效果：剧作家选择放置或移除目标 1 枚不安。
- 剧作家能力阶段中，角色不能通过无视友好拒绝剧作家使用该能力。

推进规则：

- 跳过或完成能力后，可用 `advancePhase` 进入 `protagonist_ability`。
- 当前未强制要求“所有可用能力都必须处理”。

## `protagonist_ability` - 主人公能力阶段

允许命令：

- `requestProtagonistAbility(state, { actorId, skillId, targetType, targetId, option })`
- `respondProtagonistAbility(state, { approved })`
- `advancePhase(state)`

候选过滤：

- 当前阶段必须是 `protagonist_ability`。
- 游戏状态必须为进行中。
- 不能存在待审批能力。
- 角色必须生存。
- 角色友好必须达到技能门槛。
- 技能必须可由主人公使用。
- 技能本日或本轮尚未使用过。
- 技能必须存在结构性可选对象。
- 候选过滤不因角色身份具有“无视友好”或“强制无视友好”而移除能力；身份只影响后续审批结果。

重要规则：

- 候选过滤不检查目标当前是否会产生实际变化。
- 例如男学生与女学生同区域时，即使女学生没有不安，男学生“移除同区域学生不安”的能力仍可宣告发动。
- 是否实际移除指示物由结算阶段决定；没有变化时记录日志。
- 候选过滤也不检查身份是否会拒绝能力。即使医生等角色的身份具有“无视友好”或“强制无视友好”，主人公方仍可在友好和对象条件满足时宣告发动；这本身是主人公获取身份信息的方式之一。

审批规则：

- 角色身份没有“无视友好”特性：能力自动接受并立即结算。
- 角色身份具有“强制无视友好”特性：宣告成立，但能力自动拒绝。
- 角色身份具有“无视友好”特性：写入 `pendingDecision`，等待剧作家接受或拒绝。
- 审批是逐能力进行的。每宣告一项能力就进入审批或结算，完成后才能选择下一项能力。

拒绝结算：

- 能力被拒绝后，记录能力未生效。
- 当前实现会把该技能标记为已使用，避免同一天或同一轮重复宣告同一技能。

已实现的主人公能力效果：

- 男学生 / 女学生 `student_reduce_paranoia`：目标为同区域另一名学生，目标移除 1 枚不安。
- 偶像 `idol_reduce_paranoia`：目标为同区域另一名角色，目标移除 1 枚不安。
- 偶像 `idol_add_goodwill`：目标为同区域另一名角色，目标增加 1 枚友好。
- 医生 `doctor_adjust_paranoia`：目标为同区域另一名角色；根据 `option` 放置或移除 1 枚不安。若医生身份具有无视友好，则需要剧作家审批。
- 巫女 `shrine_remove_intrigue`：巫女必须位于神社；神社移除 1 枚密谋。
- 巫女 `shrine_reveal_role`：目标为同区域角色；目标身份公开。
- 职员 `worker_reveal_self`：目标固定为职员本人；职员身份公开。
- 医生 `doctor_patient_mobility`：记录本轮住院患者可离开医院的日志；后续还需要接入实际禁行豁免状态。

推进规则：

- 主人公方可用 `advancePhase` 结束能力阶段并进入 `incident`。
- 存在 `pendingDecision` 时不能推进。

## `incident` - 事件阶段

允许命令：

- `advancePhase(state)`

结算规则：

- 查找当前日期的预定事件。
- 若当天没有预定事件，记录“今天没有预定事件”。
- 当前只实现事件类型 `suicide`。
- 未实现的事件只向剧作家记录“尚未实现”的隐藏日志。

自杀事件：

- 若当事人已死亡，事件不发生，并向剧作家记录原因。
- 若当事人的不安小于不安限度，事件不发生，并向剧作家记录当前不安。
- 若当事人的不安达到或超过不安限度，事件发生，当事人死亡。
- 如果死亡角色身份为关键人物，当前轮回立即失败。

推进规则：

- 若事件导致轮回失败，阶段会进入 `loop_end` 或 `final_guess`。
- 若游戏仍为进行中，进入 `leader_rotation`。

## `leader_rotation` - 队长轮换阶段

允许命令：

- `advancePhase(state)`

结算规则：

- 纸质规则中，队长牌交给当前队长左手边的主人公。
- 当前本地原型尚未建模玩家座次；本阶段会记录队长轮换日志，然后进入 `end_of_day`。
- 主人公行动位仍按绿、红、蓝固定顺序表现每回合三套主人公手牌。

## `end_of_day` - 回合结束阶段

允许命令：

- `advancePhase(state)`

结算顺序：

1. 检查杀人狂。
2. 检查杀手。
3. 若游戏仍为进行中，执行换天或胜利判断。

杀人狂：

- 基于回合结束阶段开始处理时的生存角色快照判断。
- 若角色身份为杀人狂，且同区域恰好只有 1 名其他生存角色，则那名角色死亡。
- 同一时点触发的多个杀人狂能力会同时结算；例如两名杀人狂彼此独处时会同归于尽。
- 该触发原因只在剧作家视图中记录。
- 若死亡角色为关键人物，轮回立即失败。

杀手：

- 遍历所有生存角色。
- 若角色身份为杀手，且杀手自己身上有 4 枚或以上密谋，主人公死亡，轮回失败。
- 否则，若同区域存在身份为关键人物、且身上有 2 枚或以上密谋的生存角色，那名关键人物死亡。
- 若关键人物死亡，轮回立即失败。

换天或胜利：

- 若当前日数已达到剧本每轮天数，且没有触发失败条件，主人公胜利，游戏进入 `finished`。
- 否则日期加 1，阶段回到 `dawn`。
- 换天时清空暗置区、剧作家本日能力使用记录、主人公本日能力使用记录和待审批状态。
- 每轮弃牌堆与每轮能力使用记录不会在换天时清空。

## `loop_end` - 轮回失败后的等待状态

允许命令：

- `startNextLoop(state)`

进入规则：

- 当角色死亡或主人公死亡触发失败条件时进入。
- 如果当前已经是最后一轮，通常不会进入 `loop_end`，而是进入 `final_guess`。
- First Steps 模组取消最终决战，因此最后一轮失败会直接进入 `finished`，剧作家胜利。

开始下一轮：

- 只能在 `loop_end` 使用。
- 轮回数加 1，日期回到第 1 天。
- 阶段回到 `dawn`。
- 盘面恢复到剧本初始状态。
- 暗置区清空。
- 每轮弃牌堆清空。
- 剧作家本日能力、主人公本日能力、主人公本轮能力使用记录清空。
- 事件日志保留，并追加新轮回开始日志。

## `final_guess` - 最终决战

允许命令：

- `submitFinalGuesses(state, guesses)`

进入规则：

- 最后一轮也失败时进入。
- First Steps 模组不会进入本阶段。
- 进入本阶段前，盘面会复原到轮回开始状态：角色复活并回到初始区域，角色和版图指示物清空，暗置行动牌和本日能力记录清空。

结算规则：

- 主人公提交每名角色的身份猜测。
- 若所有角色身份都猜对，主人公胜利。
- 只要有至少 1 名角色猜错，剧作家胜利。
- 结算后游戏进入 `finished`。

当前限制：

- 第一版一次性提交全部猜测。
- 尚未实现更细的最终决战 UI 流程或逐角色确认流程。

## `finished` - 游戏结束

允许命令：

- 规则核心中没有进一步结算命令。
- UI 可以重新创建 `GameState` 以重开。

进入规则：

- 某轮结束时没有达成失败条件，主人公胜利。
- 最终决战完成后，根据猜测结果决定胜负。

## 失败条件与阶段跳转

当前统一由 `failLoop` 处理轮回失败：

- 记录公开失败日志。
- 记录剧作家可见的隐藏失败原因。
- 若当前轮回数小于剧本轮回上限，进入 `loop_end`。
- 若当前轮回数已达到剧本轮回上限，且剧本允许最终决战，复原盘面后进入 `final_guess`。
- 若当前轮回数已达到剧本轮回上限，且剧本取消最终决战，进入 `finished` 并判定剧作家胜利。

当前可触发失败的已实现原因：

- 关键人物死亡。
- 主人公死亡。

当前能导致关键人物死亡或主人公死亡的已实现来源：

- 自杀事件。
- 杀人狂回合结束能力。
- 杀手回合结束能力。
