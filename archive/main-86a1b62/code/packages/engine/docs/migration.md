# 迁移路线

当前旧 Web 原型继续运行；独立 package 逐阶段推进，不从旧代码导入任何规则或执行函数。

接入每条真实规则时：

1. 在根目录 facts/ 找到来源与人工审阅结论；不确定性记录在事实区或已知误解文档。
2. 写出触发时机、条件、选择归属、效果、可见性和例外，列出至少一个人工判定样例。
3. 确认当前表达语言能够完整表示；缺少机制时先设计并验证机制，不将效果降级为日志。
4. 添加声明与测试，更新模组/剧本完整性清单。对新旧差异逐项查证，不以旧实现为最终裁判。
5. CLI 验证后接入 Web 适配；遵循仓库的真实 GUI 人工体验与部署流程。

工程文档保存在 package/docs；源游戏资料和结构化事实保存在根目录 facts。旧 docs/architecture 文档描述旧原型，不自动约束新引擎的实现。
