# 项目愿景

状态：草案  
最近更新：2026-06-21

## 项目目标

这个项目希望把《惨剧轮回 / 惨劇RoopeR / Tragedy Looper》整理成可教学、可校对、可在线游玩的数字原型。

近中期目标分三条线推进：

- 资料整理：保留来源、日期、术语差异和待校对项，避免复制长篇规则书或卡牌全文。
- 新手教学：维护 spoiler-light 的 Marp deck，帮助新玩家快速理解轮回、暗置行动、事件和最终决战。
- 在线原型：实现 Web-first 的游戏界面和 UI 无关规则核心，为后续联机打底。

## 技术方向

项目采用 Web-first 实现。除非明确需要桌面离线版，不再维护 PySide 或其它第二套 GUI。

当前结构：

- `code/web/`：浏览器原型。
- `code/web/core/`：规则核心，浏览器和 Node 测试共用。
- `code/src/tragedy_loop/app.py`：本地静态 Web 服务入口，用于 `uv run tragedy-loop`。
- `products/slides/`：Marp 教学材料。
- `docs/`：架构、开发流程和项目说明。
- `facts/research/`：带来源链接的公开研究笔记。
- `facts/structured/`：程序可读取的结构化资料草稿。
- `facts/source_material/`：本地参考资料与 OCR 整理。

## 在线版方向

最终在线版应具备：

- 剧作家与主人公不同视图。
- 隐藏信息的服务端权威保存。
- 行动牌暗置、同步揭示、日志回放。
- 断线恢复和旁观/复盘能力。
- 主人公方讨论与队长行动分派。
- 可逐步增加剧本、惨剧模块、身份和事件。

第一阶段只追求新手剧本闭环。核心标准是：能完整跑完一局、记录每一次状态变化、明确隐藏信息边界。

## 内容边界

项目不应把扫描件、长规则书文本或卡牌原文大量复制到公开资料中。优先记录：

- 标识符。
- 简短规则摘要。
- 结构化字段。
- 来源链接或本地来源位置。
- 待校对状态。

这样既方便开发，也能减少版权和剧透风险。
