# 项目愿景

状态：草案  
最近更新：2026-06-21

## 核心目标

本项目希望把《惨剧轮回 / 惨劇RoopeR / Tragedy Looper》整理成一套可追溯、可教学、可在线游玩、可扩展分析的数字化工程。

目标不是简单复刻一份规则书，而是建立从事实来源到规则模型再到交付产物的连续链路：

1. 事实层可追溯：纸质版、公开资料和人工输入都保留来源、校对状态和结构化摘要。
2. 规则层可执行：在线版使用 UI 无关的状态机表达行动、能力、事件、死亡、失败和轮回。
3. 产物层可交付：资料站、新手教学、在线对战、推理辅助和剧本工具都能从同一套事实与规则模型生长出来。

## 三条产品线

### 资料整理与资料站

资料站应面向查阅、教学和校对：

- 保存规则、术语、角色、身份、事件、惨剧模块和剧本的结构化索引。
- 提供新手教学内容，优先保持 spoiler-light，让新人能快速理解轮回、行动暗置、事件、失败条件和最终猜测。
- 对来源、日期、版本差异和待校对项保持透明。
- 避免长期保存大段规则书原文或卡牌全文，优先使用摘要、标识符和出处引用。

### 在线版游戏

在线版采用 Web-first。基础功能目标是支持与纸质版体验一致的对战流程：

- 剧作家与主人公使用不同视图，隐藏信息由权威状态保存。
- 支持行动牌暗置、同步揭示、移动和指示物结算。
- 支持角色能力、身份能力、事件、回合结束能力、死亡、失败条件、换天、轮回重开和最终猜测。
- 支持日志回放、状态投影和断线恢复的架构准备。
- 未来支持多名主人公在线协作、队长确认和行动分派。

第一阶段只追求新手剧本闭环：能完整跑完一局，记录每一次状态变化，并清楚区分公开信息与隐藏信息。

### 扩展工具

规则核心稳定后，扩展两类工具：

- 推理辅助：从规则约束、可能世界枚举、剪枝搜索和可解释提示起步；在有足够数据和明确任务后，再评估是否引入深度学习。
- 剧本制作与校验器：支持剧本编辑、角色与身份分配检查、事件日程检查、规则模块兼容性检查、失败条件可达性分析和自动化回放验证。

## 技术方向

- Web-first：除非明确需要桌面离线版，不再维护 PySide 或其它第二套 GUI。
- 规则核心 UI 无关：核心状态机位于 `code/web/core/`，浏览器和 Node 测试共用。
- Python 只承担本地服务、资料处理和工程脚本：入口位于 `code/src/tragedy_loop/app.py`。
- 事实数据与代码分离：结构化资料位于 `facts/structured/`，扫描和审阅稿位于 `facts/source_material/`。
- 交付产物集中管理：Marp slides 和未来资料站/静态构建输出位于 `products/`。

## 当前结构

- `facts/`：事实区，包含扫描归档、人工审阅稿、公开研究和结构化事实数据。
- `code/`：源代码区，包含 Web 原型、规则核心、Python 服务、处理脚本和测试。
- `products/`：产物区，包含 Marp 教学材料和构建后的静态预览。
- `docs/`：项目文档区，包含架构、录入流程、已知误解和本愿景。

## 内容边界

项目不应把扫描件、长规则书文本或卡牌原文大量复制到公开资料中。优先记录：

- 标识符。
- 简短规则摘要。
- 结构化字段。
- 来源链接或本地来源位置。
- 待校对状态。

这样既方便开发，也能减少版权和剧透风险。
