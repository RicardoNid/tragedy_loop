01 · 结论与交付边界

不能把当前实现声明为“剪枝不会误删”。

已复现：周年模式无条件要求恰好一名因果残片，会删除“没有平民、允许不追加残片”的合法规则组合。开局校验器与离线枚举器共享这一假设；现有回归全部通过，仍未发现该问题。

审查重点为当前导出的 LiveKnowledge：规则组合与候选域、约束传播、因果来源、事件判定、隐藏历史搜索、增量缓存及公开契约。实际实时求解器仅声明支持 FS / BTX；其他模组的例外用于限定规则边界，不表示本方案已经审完或支持全部模组。

规则依据采用仓库当时的本地资料及其来源约定（wiki > lloyd > ricardo），没有重新联网校订。核心资料快照多采集于 2026-09-27；本报告日期不是来源更新日期。工程中的 Q1–Q3 已确认裁定同时纳入结算与跨轮边界。没有修改 facts/、源码、测试、锁文件或既有报告。

“证明”分层：以下给出数学证明或证明草案，说明前提满足时为何不误删；不宣称规则翻译、编译器、运行时已获得机器检查的完整证明。当前实测、建议新增测试和待核对语义分别标明。

02 · 统一正确性标准

设 Fₜ 是指定规则版本、公开开局、全部已知观察共同定义的完整历史公式；Kₜ 是快速剪枝保存的符号约束。允许 Kₜ 多保留未知解释，但必须始终满足：

Models(Fₜ) ⊆ Models(Kₜ)

每条规则：R ∧ Scope ∧ Premises ⇒ Conclusion
每次更新：Kₜ₊₁ = Propagate(Kₜ ∧ 新观察的必要条件)
每次删除 x=v：证明 Kₜ ∧ (x=v) 不可满足，或使用已证明的局部传播规则。
不能把“暂未找到支持”“未实现”“预算用尽”当成不可满足。

一条真实历史能映射到旧约束的解，且每条新约束都是该历史的必要条件，就仍能映射到新约束的解；对信息到达次数归纳，可证明整个剪枝链不误删。这个结论依赖初始域覆盖完整、规则前提真实、观察权限正确和每一步传播可靠。

动态状态用时间下标：初始身份 I₀(c)、判定时身份 Iₜ(c)、结算批次入口位置 Lᵦ(c)。当前状态会迁移，不要求其集合简单包含于前一时刻；单调缩小的是与累积历史兼容的固定剧本假设。

固定规则版本与合法开局域→追加结构化观察→必要条件入队→相关约束传播到不动点→剩余分支按需搜索

安全的“提前建立”是预先编译效果索引、合法角色关系、身份名额与可达时点，并验证编译模板；不是提前枚举所有剧本。传播不动点仅表示这些传播器不再收紧，不等于精确解空间。

P01 · 公开开局与规则组合约束 P0

适用条件
输入是开局公开视图而非中途盘面；公开角色全集、模组、天数、轮数、事件表完整；规则版本和特规已确定。
剪枝结论
删除违反公开角色全集、日期范围、公开规则组合结构的候选。FS / BTX 的组合结构分别从对应规则包生成；未知的真实事件名仍作为条件变量保留。不以官方剧本目录是否收录作为合法性条件。
例外
转校生、神灵未登场不等于不在剧本；临时工？为替身，不是额外可自由配置的开局角色。未支持特规或无界变量不能按空域处理。
正确性证明
每个合法世界必须满足公开开局事实。角色全集或规则结构不匹配的世界与公开事实矛盾；反之，不能从“当前看不见”推出“不存在”。需要单独证明开局构造涵盖全部允许参数。
验证方法
在小角色数下独立生成合法配置，对比候选域；加入缺席角色、未收录剧本、同名不同模组、非法中途视图。未支持输入预期为 unsupported / unknown，而非 contradiction。
依据 / 实现
特殊登场角色；knowledge-domain.ts:25–60、knowledge-live.ts:34。现有初始域测试通过，但支持域守卫仍需审计，见 A03。

P02 · 身份名额与全局匹配 P1

适用条件
固定一组主副线，身份数量和上限已按该模组解释；普通分配角色集合已确定。
剪枝结论
建立“角色—身份槽位”二分图。强制 c=r 后若不存在覆盖全部必分配角色的合法匹配，删除该取值；整体无匹配时删除该规则组合。例：两人只能占两个指定槽位，其他人不能再占这些槽位。
例外
模仿犯、局外人不消耗普通名额；暴徒的可选数量不能当作固定数量；周年替换另见 P05。对同名身份叠加与上限必须依据模组，不能对所有内容采用同一解释。
正确性证明
合法完整分配必诱导一组匹配。无覆盖匹配则不存在合法分配；强制边无匹配则该边不属于任何合法分配。此证明不依赖历史搜索，但依赖槽位表正确。
验证方法
对 0–6 个普通角色、重复槽位、上限、可选身份和强制边做穷举匹配对照；独立核查来源数量。现有 Hall 集测试和初始域对照通过，不等于所有名额规则翻译已证明。
依据 / 实现
复仇的火种：主谋①、被封印的邪灵：主谋①、邪教徒①；knowledge-constraints.ts:120–160、knowledge-domain.ts:61–78。

P03 · 角色的开局身份资格 P1

适用条件
规则作用于“剧本制作时”，检查初始身份；未启用改变该资格的特规。
剪枝结论
A.I. 不分配平民；妹妹不分配带无视友好特性的身份；BTX“和我签订契约吧！”为关键人物施加少女属性约束。
例外
后续身份转变不是开局非法。局外人与模仿犯的特殊分配如何继承主线限制，应逐项核对：当前代码对该主线的局外人作豁免，不能仅凭代码把豁免当作已证规则。双面身份不在当前实时支持域。
正确性证明
角色／规则条目明确禁止的初始分配不是合法开局，因此可以在历史展开前删除。对存在豁免争议的分配，应保留或隔离为未验证，不得自行加强限制。
验证方法
逐个禁止身份构造负例；合法邻近身份作正例；加入妹妹的必定无视、局外人和双面身份边界。每个例外都需要来源或明确裁定。
依据 / 实现
A.I. / 特性、妹妹 / 特性、契约主线；knowledge-domain.ts:79–92。

P04 · 模仿犯与局外人的关系约束 P1

适用条件
上述角色存在，复制对象或模组身份池可枚举；使用配置身份而非当时生效身份。
剪枝结论
模仿犯必须有另一角色作为合法复制对象，身份与被复制身份满足规则规定的相等关系；局外人身份属于当前模组且不在所选规则身份池。复制对象域和身份域互相传播。
例外
模仿犯明确无视身份上限；局外人不直接视为平民，且不能作为周年残片。周年允许复制因果残片，不能仅把残片映射为平民后丢失复制关系。
正确性证明
对每个身份取值必须存在至少一个合法复制对象及相容身份；若所有支持均不存在，该取值不能扩展成合法配置。局外人的补集域直接来自其特性。关系投影的安全性不等于关系全部满足。
验证方法
枚举复制对象×初始身份，检查自我复制、唯一对象、配额超限例外、残片复制及局外人禁止项。普通复制回归已通过；残片复制需新增来源级用例，见 A02。
依据 / 实现
模仿犯、局外人、基础 FAQ 第112–113行；knowledge-domain.ts:94–100,158–193。

P05 · 周年残片的有条件追加 P0 · 当前存在误删

适用条件
启用本地 FAQ 所述“+规则”，普通身份分配已完成，哪些角色有资格作为平民被替换已明确。
剪枝结论
有合格平民时，选择一名作为追加的因果残片；没有平民时，允许不追加。使用独立变量“被选中的原始角色”，不要把“所有最终残片身份总数恰为1”直接作为通用约束。

P06 · 事件真实类型与当事人分配 P1

适用条件
事件日期与公开名称已知；每个真实事件的当事人种类、复用许可已编译。
剪枝结论
保持二元关系“真实事件类型 ↔ 角色／区域当事人”。普通事件采用互异约束；只有所有相关真实事件确实禁止复用时，才能用全局匹配提前删除无支持的当事人。公开名与真实名不一定相同。
例外
连续杀人有重复当事人许可；群体事件以区域为当事人；伪造事件允许不同公开名；临时工存在替身触发。跨模组不能只按中文名称判定许可。
正确性证明
合法事件表必满足类型关系和该类型的复用限制。对候选四元组（类型₁、当事人₁、类型₂、当事人₂）枚举支持，只删除没有合法支持的值，保留条件依赖。
验证方法
两事件×三角色穷举：普通/普通、连续/连续、连续/普通、伪造候选、区域当事人。比较完整联合配置，不能只比较每列候选。现有复用回归通过；扩模组时重新验证复用语义。
依据 / 实现
基础 FAQ 第69–73行；HS 连续杀人（扩展例外，不是 FS 的内容声明）；knowledge-domain.ts:194–250。

P07 · 普通事件发生的必要条件 P1

适用条件
收到明确的 occurred=true 事件记录；对应日期、事件阶段和判定前状态可靠；适用封闭的普通触发模型。
剪枝结论
删除已知在判定时不存活，或已知触发数值不足的“真实事件—当事人”组合。仅删除该组合，不能一概删除角色或事件。
例外
A.I. 的普通不安触发使用所有原始指示物之和；希望／绝望影响有效数值；事件可能改用密谋或友好并有阈值偏移。临时工替身、群体事件、强制触发身份等需独立模型或保留。
正确性证明
已证“发生 ⇒ 存活 ∧ 数值达标”的封闭模型中，某一必要条件确定为假即矛盾。只要存在替代触发路径，就不能使用该蕴含，必须先加入替代路径的析取。
验证方法
阈值−1、阈值、阈值+1；死亡/缺席；AI 多种指示物；希望/绝望；原始与有效量；事件阈值偏移。与事件引擎判定对照，并另用来源算出期望值。已有相关回归通过。
依据 / 实现
基础 FAQ 第73行、AI；knowledge-scope.ts:522–607、engine.ts:1073–1175。

P08 · 明确“未发生”的反向剪枝 P2

适用条件
记录明确为 occurred=false；判定已完成；已证明当前类型具有充要触发条件，而非只有发生的必要条件。
剪枝结论
若在所有允许的隐藏状态中该候选都必然触发，就排除该候选。存在任何合法阻止原因时仍保留。
例外
手下成功使用能力可禁止本轮事件；隐藏的发动记录不可按不存在处理。预言家、特殊规则、轮回中断等都可能破坏普通充要条件；当前实现针对部分身份与主线整体跳过。
正确性证明
只有“候选 ∧ 已知状态 ⇒ 必然发生”与未发生记录矛盾；“达到阈值 ⇒ 可能发生”不足以排除。对未知阻止标记存在量化，不能默认为 false。
验证方法
同一公开数值分别构造有/无隐藏禁止效果；两者应有不同可行历史。测试未到事件阶段、已中断和明确 false 的区别。增量与从头求解对照。
依据 / 实现
手下友好能力；knowledge-scope.ts:529–576。新增规则影响触发时必须使封闭模型证明失效，见 A03。

P09 · 效果观察、事件发生与事件完成分离 P0

适用条件
任何涉及盘面变化、事件记录或完成后触发的推理。
剪枝结论
盘面效果只约束可能来源；只有明确发生记录才约束事件发生；只有完整完成证据才约束完成后能力。三者分别建变量，不能互相直接等同。
例外
AI 调用事件效果不视为事件发生；黑猫当事人的事件效果为无现象；医院无密谋时事故可发生但无现象；教主重复结算事件文字，不应误算成两次独立发生。
正确性证明
每个上述例外都是“相同效果对应不同发生状态”或“发生但无效果”的构造性反例。故反向等价不成立；只有保留三种状态并按其正式规则连接才不排除这些历史。
验证方法
四组配对轨迹：AI/正常事件、黑猫/普通当事人、医院0/1/2密谋、教主/普通角色。再加入事件中断，检查完成后触发不得提前成立。
依据 / 实现
医院事故 FAQ、黑猫、教主、Q2 裁定；knowledge-scope.ts:522。

P10 · 区域密谋增加的来源析取 P1

适用条件
已知同一观察阶段区域密谋净增加；来源索引覆盖本规则包所有能够产生该观察的路径。
剪枝结论
至少存在一个合法的正向来源。加入“主谋角色来源 ∨ 流言四起规则来源 ∨ 其他合法来源……”；仅当所有来源都不可能时删除候选规则组合。
例外
传谣人身份加的是不安，不是“流言四起”规则的区域密谋。复合增减不能凭净+1推出能力量恰为1。间接调用、延迟、强制后续、移动尸体类等均需覆盖；未识别来源采用无条件保留支路。
正确性证明
真实净正增量必须包含至少一项正向贡献或其他已建模增量机制。若来源索引是这些机制的超集，每条合法历史都至少支持一个析取分支；多列只会少剪，漏列会误删。
验证方法
逐个效果指令编译测试；对每条引擎真实区域增量，断言其来源至少被一个候选覆盖；净+2−1、间接调用、全局规则、未知指令和多来源同时结算均作正例。
依据 / 实现
FS 主谋、FS 传谣人、FS 流言四起；knowledge-effects.ts:36、knowledge-scope.ts:387。

P11 · 来源的时点、目标与区域可达性 P1

适用条件
已建立 P10 来源集合；具体能力的作用时点、目标类型与有效区域已知。
剪枝结论
排除错误阶段、只能作用角色却解释区域、或不可能到达目标的来源。来源不合格只删除该原因支路，不直接删除来源角色的身份。
例外

P12 · 发动前提与三值计算 P1

适用条件
要解释某效果的来源存在必要条件；前提值来自该发动／结算批次入口快照，或是不会随状态变化的静态事实。
剪枝结论
仅在必要条件确定为 false 时删除来源；true 保留，unknown 也保留。未绑定变量、未公开状态、非安全快照一律不能猜值。
例外
妹妹能让成人忽略友好数量使用能力；代理发动或间接调用必须使用对应许可，不套原始门槛。强制同时效果不能用逐条发布后的中间盘面回判前提。
正确性证明
抽象计算的 false 必须保证所有具体化都为假；unknown 代表真/假均可能。NOT unknown 仍为 unknown，OR 只在所有分支为假时为假；这些算子保持保守性。
验证方法
三值真值表；缺失属性；希望对友好阈值的修正；多步骤及同时效果先改变条件的反例；忽略门槛调用。现有三值、绑定和同时效果回归通过；这不是 safeSnapshot 判定的完整证明。
依据 / 实现
妹妹友好能力、结算批次裁定；knowledge-conditions.ts:84、knowledge-effects.ts:43–50。

P13 · 单阶段与单轮资源容量 P1

适用条件
能力次数上限、共享使用键和每次发动最多产生的相关观察条数已证明；计数窗口相同。
剪枝结论
设来源 s 剩余可用次数为 uₛ，每次至多产生 bₛ 条相应记录。分配给该来源的记录数不得超过 uₛ·bₛ；关联观察不满足容量约束时删除该联合解释。流言四起每轮限一次，是优先应用点。
例外
一次能力可影响多个区域；一条净增量记录也可能包含多个来源。共享次数不能按角色拆开；拒绝是否消耗必须按版本；未知上界取无穷大，不能猜成1。
正确性证明
每条真实正增量记录选一个实际正向来源作为见证。只要每次发动的记录上界未低估、剩余次数未低估，这些见证可映射为一个满足容量的分配。容量无解才能排除。不能先贪心把第一条观察永久记在某来源上。
验证方法
1次影响4区、两来源合成1记录、跨日与跨轮、共享key、拒绝与调用、未知上界；枚举小型来源分配检查无误删。现有容量与预算测试通过。
依据 / 实现
BTX 流言四起、FAQ 第99–100行（WM拒绝例外）；knowledge-scope.ts:206、knowledge-causes.ts:59–132。

P14 · 跨观察的共同身份与容量约束 P1

适用条件
多条观察共享初始身份变量、身份配额或能力资源；相关来源已满足 P10–P13 的保守性要求。
剪枝结论
联合选择每条观察的至少一个解释，要求同一角色的身份选择一致、配额及资源不超限。对某候选值强制赋值后全部解释无解，才删除该值。
例外
模仿犯与局外人不占普通配额；身份会变化时，应共享初始身份并通过转换关系连接各时点，不能要求当前身份永远相同。达到局部预算不视为无解。
正确性证明
任何真实历史为所有观察同时提供一组身份一致且资源合法的见证。联合必要条件的交集仍包含该见证；反复传播只删除无支持值，因此可递归复用。
验证方法
“一名主谋＋一次流言”解释两个区域保持歧义，第三个独立区域在封闭前提下才矛盾；随后公开身份反向传播；加入模仿犯后不能沿用单主谋容量。已有小型独立枚举 oracle 回归通过。
依据 / 实现
P02、P04、P10、P13 的合取；knowledge-causes.ts:28–132。推导规则，不是新的游戏规则。

P15 · 延迟效果的可达日期 P2

适用条件
效果有明确的调度时点与到期表达式；日期、轮次的有限范围已知。
剪枝结论
只有不存在任何合法的先前发动日期、轮次、阶段能调度到当前观察时点时，才删除延迟来源。
例外
当日同阶段立即到期、跨轮、嵌套调度、未知日期表达式、执行时身份与原发动身份不同。未知表达式不能转为默认日期；观察到期位置不代表当时发动位置。
正确性证明
若该来源实际产生观察，就必有一个合法调度起点。枚举或符号约束覆盖全部可能起点而无解，才可排除。对未知表达式扩大可达集合保持安全。
验证方法
固定日、相对日、跨轮、当日立即执行、嵌套调度和未知表达式；与实际调度器比较。已有日期回归通过，未证明任意调度程序完备。
依据 / 实现
效果程序中的 schedule 语义及 Q3 跨轮边界；knowledge-effects.ts:87–100、knowledge-scope.ts:164–204。未逐项核验的其他模组延迟规则不启用强剪枝。

P16 · 正式公开与动态身份的前像 P0

适用条件
公开记录真实可靠，且已知它公开的是规则、当事人、配置身份还是当前生效身份。
剪枝结论
直接公开规则／当事人可收紧对应静态变量；公开当前身份 r 时，保留所有可能经合法转换到 r 的初始身份，即计算转换关系的前像。
例外
BTX 妄想扩大病毒可使平民暂变杀人狂；临时工覆盖身份；扩展模组可能存在公开伪装。推理唯一不等于正式公开，不能因此触发亲友等游戏效果。
正确性证明
真实初始身份在该时点必有一条合法转换映射到公开结果。删除所有没有映射的初值安全；把当前身份与初始身份直接相等，会删除存在转换的合法历史。
验证方法
病毒前/后/恢复、临时工与替身、正式公开与推理唯一；对支持域内每一种身份变化列完整前像表。现有代码只显式照顾部分特例，应阻止无审查扩模组。
依据 / 实现
BTX 妄想扩大病毒、临时工；knowledge-domain.ts:262–286。

P17 · 不能从“未观察到”直接否定能力 P0

适用条件
只有在证明某候选必定触发、结算未被阻断且必定公开指定记录，并且该观察窗口已结束时，才允许使用缺失记录。
剪枝结论
候选必然产生可见记录而实际没有，排除该候选。可选能力、隐藏记录和未结束窗口不得用此规则。
例外
可选能力未发动、无视友好、保护或替代、无现象、立即结束的未开始后续。关键人物死亡不必额外公开其身份，不能据此删除关键人物假设。
正确性证明
需有完整蕴含“候选 ⇒ 必出现可见记录”。缺失记录只是否定后件；没有这个强蕴含就不能逆否推理。
验证方法
构造成对世界，分别为强制/可选、公开/隐藏、有/无中断、护卫/无护卫；所有允许无记录的世界必须保留。
依据 / 实现
医院事故中的关键人物无需额外声明、Q1–Q2。建议新增通用规则，当前未见统一的可见性证明系统。

P18 · 只重算依赖分量与安全状态合并 P1 / P2

适用条件
变量、条件读取、共享配额、资源、跨轮引用和来源闭包的依赖图完整。
剪枝结论
新信息只唤醒受影响的连通分量；不相关分量保持原约束。仅当两个状态对全部未来合法行为与公开观察等价时，才可合并。
例外
共享身份名额或每轮次数会连接看似独立的角色；正式公开标记、事件发生记录、次数和延迟队列会使相同盘面有不同未来。共享规则组合不能遗漏。
正确性证明
真正分离的约束合取在各分量独立求解，局部传播保持相同解集。状态合并要求未来观察等价（或经过证明的双模拟），仅盘面相等不是充分条件。
验证方法
依赖传播与全量传播对照；新增跨分量资源后必须合并；中途添加约束与暂停分支恢复；相同盘面但不同次数、正式公开、延迟任务的反例必须不合并。
依据 / 实现
P02、P13–P17 的依赖；knowledge-constraints.ts:25–91、knowledge-causes.ts:28–58。现有依赖索引测试通过；任意未来等价合并尚非已验证功能。

P19 · 无合法历史支持才删除固定配置 P2

适用条件
固定配置仍符合快速约束，隐藏选择枚举完整，观察顺序与投影一致。
剪枝结论
找到一条合法历史即可标记该配置“可能”；穷尽所有合法历史且无匹配才排除。对某变量值，需穷尽所有含该值的配置及路径才能全局删除。
例外
单个见证失效不能删除整个配置；其他隐藏行动分支要保留。预算、暂停、不支持输入、缺失玩家选择只能得到 unknown；不能裁剪成有限深度后假称穷尽。
正确性证明
合法性的量词是“存在配置且存在历史”。否定存在必须排除全集中的所有分支；一个可检查见证足以证明存在，却不能代表所有后继。
验证方法
第一条见证失效而第二条仍成立；按单条/不同分批追加；暂停恢复；和从头完整重算对照。现有多隐藏牌、预算恢复、增量对照测试通过，但与规则引擎共用语义的盲区仍在。
依据 / 实现
逻辑量词规则；knowledge-history.ts:67–149、knowledge-live.ts:234–329。

P20 · 超时、重放与修正不得伪装成剪枝 P0

适用条件
所有运行阶段、缓存命中、观察追加和规则版本切换。
剪枝结论
只有已证冲突进入排除缓存；unknown 保留。重复观察幂等；旧观察或规则被修正时，从相应版本重建，不能继续沿用此前的单向删除。
例外
搜索顺序可影响中间进度，不应影响完成后的语义结果。毫秒预算导致中间结果不同不等于算法错误；可复现实验应使用工作步数并固定排序。
正确性证明
追加条件只会使已证不可能仍不可能，因此原有排除可复用；撤销或改写条件不具备这一单调性。预算未完成没有提供任何“不存在”的证明。
验证方法
预算0/1/不同步数；重复包、重叠包、乱序包；同前缀恢复；规则摘要变化；观测更正后的从头重放。现有重复追加与预算测试通过；规则更正需要另建版本分支。
依据 / 实现
knowledge-live.ts:81–163,270–343、knowledge-causes.ts:97–132；当前 append 明确禁止改写历史，符合单调缓存前提。

A02 · “残片恰一名”与模仿犯复制的语义冲突 高 · 静态证据，未完成对局复现

FAQ 第113行允许模仿犯复制因果残片。当前 baseIdentity 把周年标记转为平民，复制关系按基础身份相等；exactlyOne 又统计所有角色的残片标记。setup.ts:379 仅让一个 anniversaryFragment 角色获得残片初始身份。

风险：若复制残片要求复制后也具有残片身份与能力，则当前表示不能表达“被追加者＋复制者同时为残片”，会漏掉合法世界，或把复制者错误保留为普通平民。这与 A01 的零平民问题不同。

建议：分离“追加选择变量”和“复制后的身份／能力关系”，避免用单个布尔标记兼任两种概念。

A03 · 支持域与封闭模型的前提不够显式 高 · 条件性误删风险

knowledge-live.ts:34–43 主要检查模组名、可见仙人和规则支持／双面身份。knowledge-scope.ts:529–549 用身份名称白名单和少量主副线名称决定普通事件模型可用。

触发条件：将来同名规则语义更新、追加会强制／禁止事件的能力、输入包含未编译特规，或外部传入变更后的 RulePack，而这些检查仍通过。事件充要条件或来源闭包可能随之失效，导致错误过滤。

边界：未发现当前默认官方 FS/BTX 对局可凭此直接触发误删；这不是现成官方反例。问题是名称守卫本身不足以证明语义封闭。

建议：规则包生成 triggerModel / identityTransitions / observationCoverage / specialRulesSupported 能力清单；剪枝规则逐项要求能力证明和版本摘要。不满足则降级 unknown，而不是沿用普通模型。

A04 · 来源编译与容量上界仍是可信核心 高 · 证明缺口，未复现默认包误删

knowledge-effects.ts:16–34,36–145 手工分类效果并估计 reports；knowledge-scope.ts:206–246 将其转为次数容量。未知操作默认保留来源，间接调用保留通配来源，都是正确的保守措施。

但对每个被忽略的操作，仍须证明它不会直接或通过规则后续产生观察；对有限 reports，须证明没有低估。一次发动到多条公开记录的映射、共享资源和强制后续是审查重点。当前 tests 覆盖若干合成效果，不是对全部指令和组合的闭包证明。

建议：以效果解释器的每个操作为单位建立编译引理；新增操作如果未有摘要就强制返回未知来源/无限容量。对每条真实增量记录运行“至少有一个来源覆盖”的审计模式，再启用对应硬剪枝。

A05 · 快照安全性与身份前像依赖特例表 中高 · 扩展时的误删风险

knowledge-effects.ts:43–50 仅在非强制、单步骤、单计数效果等条件下使用动态快照；其余保守跳过。knowledge-domain.ts:272–286 对临时工和病毒公开身份作特例。

这些保护已覆盖已读回归中的同时结算和病毒场景；本次没有新的默认包反例。风险在于把语法上的“单计数操作”当成足够的快照证明，以及新增身份转换时忘记扩展前像表。

建议：给观察附结算批次／生效时点（若契约允许），或证明当前串流足以重建；在编译期统一生成身份转换关系。不能扩大 safeSnapshot 范围仅为提升命中率。

A06 · 暂停分支不自动获得新增关系 中 · 主要是漏剪与额外搜索风险

knowledge-constraints.ts:82–91 克隆当前约束列表；assignments 恢复时通过 current 只交叠最新变量域。新加的关系本身不会自动进入已暂停的克隆，即使它的单变量投影未变化。

这通常使分支多保留候选，而不是误删；后续完整历史验证仍承担合法性检查。因此不能把它写成已确认的不安全剪枝。

建议：给关系集加版本，恢复时安全同步或重建分支约束；确保新增关系的解释闭包完整。验证“新增关系但域不变”的例子，而非只验证依赖索引未被破坏。

A07 · 参考求解器不是完全独立的规则裁判 高 · 已证实的验证盲区

reference.ts 复用 initialize、advance、enumerateChoices；离线枚举器也复用校验器和同样的残片假设。A01 已显示：实现对照可以全部一致，但共同偏离来源规则。

建议：将“剪枝等价于执行内核”与“执行内核符合规则来源”分开验收。增加人工推导的微型规则真值表、来源级反例和独立小模型；测试不能把主实现的结果直接作为期望。

已检查到的正向保障
