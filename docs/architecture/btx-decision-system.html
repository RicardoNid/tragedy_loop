BTX 双方决策系统技术方案

首版采用 TypeScript、Node.js 多核工作线程、按行动席位搜索的信息集蒙特卡洛树搜索，以及冻结策略参与的 CPU 自对弈。首个验收模组为 Basic Tragedy X（BTX）。程序从给定剧本开局，分别操纵剧作家和三个主人公席位，效用取整局胜负。完成一次轮回、探明一个身份或诱导对方误判的价值，由其后续整局结果体现。

一、先打通席位视野

设剧作家盖完三张牌，第一名主人公已盖牌，轮到第二名。第二名知道每张牌的持有者和落点，只能查看本人盖下的牌面。当前 project 对主人公使用阵营共用的历史、主人公全员手牌，并在盖牌投影中显示同阵营牌种；advance 还把主人公完整选择广播为阵营的 own-choice。仅在 UI 隐藏牌面仍会使搜索从其他字段反推答案。规则 §4.3–4.5、§6.8 · 投影 · 行动记录

先为单席提供符合规则的事件流和投影。保留公开使用状态与落点，自己的完整动作只记入本人历史。只将规则允许且实际发生的交流写入接收者历史；允许讨论不自动披露暗牌。检查菜单、手牌差分、缓存键和查询解空间的输入。剧作家知道剧本，也必须从自己的视野推演未翻开的主人公牌。

第一项验收：构造两条合法记录，保持公开动作和落点相同，只更换第一名主人公盖下的牌。在这次翻牌前，第二名主人公和剧作家的输入、候选行动及固定种子的出招应分别一致；第一名应能区分两条记录。翻牌后，其他席位应能据新观察改变策略。另测跨轮回记忆和仅凭公开结果推理隐藏原因。

二、连接已经完成的解空间

决策输入为规则版本、席位、该席可见的事件历史、自身行动记忆和当前合法选择。信息集键编码这些会影响未来决策的内容。两个历史即使版图相同，也可能因上一轮揭示过的身份而属于不同信息集。规则摘要、策略版本和模式用于缓存隔离。项目解空间定义

解空间 → 推演宿主
提出的适配接口按席位历史批量提供相容世界见证。每个见证须包含能恢复到当前节点的剧本与隐藏轨迹，或等价的可继续执行状态。恢复后重新投影并核对该席历史、待行动席位和合法菜单。若现有视野层只支持条件可行性查询，先加见证重建与批量取样适配，避免独立抽每个角色身份再拼接。
推演宿主 → 策略
完整模拟状态只交给规则引擎。每次轮到某席位，就重新投影，只传该席看得见的特征和合法行动。对其他席位调用已冻结的行为策略，训练或运行该策略时也须遵守同一信息边界。剧作家侧的见证固定自己已知的剧本、已选动作和公告，只补全其未知历史。
策略 → 实战宿主
策略返回一个公开契约中的 Choice。宿主使用当前席位端口的 revision 与 decisionId 提交；过期时重新读局面。模拟使用模拟状态自身的标识。引擎暂停时续跑，同一模拟不重复计分。真实剧本、引擎全状态指纹及真实隐藏轨迹均不用于玩家的搜索键。引擎入口

Q10 留作独立决策。原型可在手工给定的有限见证批次上运行，并记录批次、种子与覆盖范围。以下均值表示该批次和指定对手上的模拟成绩。解空间只定义支持集，生成器遍历顺序、重复见证数和抽样频率都不能直接解释为真实剧本概率。

三、在线算法：当前席位做信息集搜索

先实现可独立运行的整局 rollout 基线。每席从合法动作中保留探索概率，用简单的本席可见特征为候选排序，例如某个公开事件离触发日期还有几天、目标可见指示物与已知门槛的差距、盖牌落点是否可能抵消预期行动。基线也必须会通过、拒绝、投票和作最终猜测。随后加入单席搜索；一局中每逢新的真实决策点，轮到谁就为谁重新规划。

输入：行动席位 i 的历史、候选世界批次、冻结的其他席位策略
重复至推演预算耗尽
  从相容批次取一个世界，恢复该世界的规则引擎
  遇到 i 的决策：以 i 的观察和自身历史查树，扩展或选择动作
  遇到其他席位：由冻结策略从其自身观察选动作
  引擎执行选择并生成各席位可见的新观察
  新扩展节点后用基线推至整局结束
  以 i 所属阵营的终局效用回传到本次访问的边
根节点按访问次数选动作，平手按固定种子处理

每条边保存访问数 N 和累计终局收益 W。已访问动作按 UCT 选取，分数为 W/N + c√(log N父 / N)；新动作先探索一次。以规则允许的完整出招作为边。不同暗牌在当前席位看到相同历史时共享统计，翻牌后按新的观察分别续搜。树只在当前决策者自己的后续决策上分叉；同阵营另外两席也用各自的冻结策略。这样一个主人公不能通过搜索替队友选择只有自己知道才合理的行动。Cowling 等，Information Set Monte Carlo Tree Search

强度边界。该算法求当前席位对一组行为策略的近似最佳回应。对手在同一条模拟轨迹中保持同一策略版本。强对手模式用已有强策略快照推演；固定风格模式替换被建模一方的策略，例如提高剧作家选择“尽快结束本轮”行动的倾向。用同一批世界、候选行动、种子和模拟预算做配对比较，分别展示两模式推荐和双方模型下的交叉得分。风格效果待实战数据检验。

把推演优先用于影响胜负的分叉

  • 剧作家三张盖牌。用渐进扩展控制宽度，访问数为 N 时最多展开 max(1, ⌊k(N+1)α⌋) 个不同的完整放置组合，0<α<1。候选来自启发式提案和带种子的合法组合探索；保留未访问组合的进入机会。组合内部的选牌顺序只用于生成，整组一次提交，中间不让主人公观察或应对。
  • 主人公单张牌和小菜单。可负担时遍历全部合法动作。延迟揭牌的动作只按可观察到的持有者和落点推进对手的记忆。相同目标上的不同牌不能因当前版图相同而合并。
  • 跨轮回。第一版新叶推演到整局结束。主人公赢取 +1，剧作家赢取 −1（剧作家端反号）。某轮死亡直接交回引擎决定后续；上一轮得到的合法信息保留。若以后在叶节点截断，用自对弈学得的整局价值估计，并独立对照完整 rollout 的误差。
  • 最终决战。引擎通用枚举器跳过 guess。把见证投影到“必须回答的剧本制作完成后的身份向量”，同一答案向量聚合。普通 BTX 在答错即负、只反馈正误的条件下，考虑整组答对的价值，避免拼接各角色的边际最优身份。对一组给定权重的见证可精确选出总权重最大的答案向量，逐次提交尚未回答的一个角色，答对后约束下一次候选。未定权重时保留分组结果并标明测试批次。枚举实现 · 最终决战 §5.2

四、CPU 自对弈怎样提高棋力

  1. 冻结一组可执行的基线策略，用线上同一套搜索替当前行动席位生成训练样本。每条样本记录本席合法视野特征、候选动作特征、根访问分布和整局结果。按剧本划分训练与留出局，所有派生轨迹跟随原剧本划分。
  2. 首个学习器用 TypeScript 实现线性动作打分，合法候选上做 softmax，以搜索访问分布为目标最小化交叉熵；另用逻辑回归预测本阵营整局获胜。双方使用不同参数，主人公三席共享参数并编码队长及行动顺序。两者都可在 CPU 上批量训练。
  3. 将训练后的策略冻结为新快照，用于对手与队友的快速行动、rollout 及渐进扩展的候选排序。交替改善双方并保留旧版本。部署时当前席位仍能搜索。先独立比较仅替换候选排序、仅替换 rollout、同时替换的效果；局面价值模型待留出数据校准后再用于截断。

三名主人公共享目标，但各自持有私有历史。冻结队友做单席改进可能错过需要多人配合的策略，反复自对弈也可能产生循环。第二阶段可预先约定一组合法的团队打法，用整队自对弈评估协调收益；执行仍只读各席合法历史。若要研究混合策略或可利用性，可先在保留暗牌的小型两人零和子游戏中用 MCCFR/OOS 做对照；该子游戏的均衡结论不能移植到完整的分席 BTX。Q11 的版本晋级规则留待后续。Lisý 等，Online Monte Carlo Counterfactual Regret Minimization

五、技术栈与开发顺序

建议新增独立 TypeScript workspace packages/decision，复用现有 Choice、规则包与引擎。纯策略模块只依赖席位输入契约；负责恢复见证、推进引擎和提交命令的宿主层单独导入引擎。首个正常入口为本机给定剧本的自动对局 runner，服务接入时调用同一决策接口。试验记录采用带规则摘要、版本和种子的 JSONL；策略快照先存数值权重和特征版本。

用 Node.js worker_threads 常驻池并行独立对局，在线阶段可用根并行：各线程持有独立搜索树和见证流，按完整动作键汇总根访问次数及收益。每个线程复用规则包，成批分发见证与预算，避免逐节点传输全状态。引擎 advance 已复制输入，热路径直接调用它。分别测量见证恢复、投影、状态复制、规则推进和根合并，决定下一步优化。初始依赖以根 pnpm workspace 为准。

  1. 席位正确性与接入。完成暗牌成对测试、跨轮回观察回放和见证往返校验。用无训练策略让双方在 BTX 自动走完整局，覆盖正常胜利、轮回失败和最终猜测。
  2. 搜索基线。先单线程，再根并行。用固定公开局面和见证批次分别测主人公出牌、剧作家三牌、能力选择、最终猜测；小局面用完全枚举的同信息集策略作对照。
  3. 强度与风格。以相同剧本和种子做配对对局，分别报告两方的整局成绩、最差剧本表现及样本量；按剧本为单位给出不确定性。绘制模拟次数与成绩、耗时的关系，记录每秒引擎步数、分支数和峰值内存。暂不设硬性响应时限。
  4. 离线学习。接入策略蒸馏和对手快照，固定在线预算与无训练版本比较。若测得瓶颈是引擎复制，先优化同一内核的状态表示并用重放对照；若瓶颈在打分，再评估原生批量计算。是否采用 GPU 或重写热路径由实测决定。
