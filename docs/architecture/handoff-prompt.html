2. 工作目标

设计一个在公开规则与阵营观察历史下，保留剧本和动态隐藏状态关联的知识模块。它必须同时支持规则传播和完整历史兼容性检查，并给出可解释的可能、不可能、尚未判定及矛盾状态。

尤其遵守主方案第 7 节：合法剧本是按规则和剧本公开信息构造的，不是从剧本目录筛选的。项目是否收录某剧本不是推理信息，也不能成为未公布的概率先验。明确的公开角色全集为 8 人时，9 人剧本被排除；仅观察到某时刻版图上有 8 人，不自动等价于这个全集声明。

主人公阵营完全共享视野是正式游玩设定，不能退回个人隔离知识模型，也不能因此提前向剧作家披露主人公暗牌。十周年拒绝次数语义已由设计者确认，按主方案落实，不恢复旧版处理。

3. 设计与实验任务

A. 知识表示与信息点传播

在已确认有限逻辑语言上，设计变量、候选域、联合约束、时间作用域、证据与推论依赖。说明哪些是权威输入，哪些是可重建缓存，哪些只是 GUI 查询投影。

给出传播规则声明形式、工作队列、去重、全局数量／互斥交互和固定点伪代码。规则传播应健全；不能将固定点当作完整逻辑闭包，也不能把推论写回直接观察历史。

比较不同来源的命题如何被引用；玩家假设不能混入真实知识约束。解释矛盾如何被发现和定位，避免无解知识库推出任意结论。

B. 全部合法剧本与完整历史兼容性

形式化初始合法构造约束、公开设定约束、已知动作、秘密选择及观察投影。给出如何从规则表达全部合法候选的路线，不以剧本目录作为枚举器的全集。

提供增量伪代码：读取新增观察、扩展历史前缀、保留所有相关秘密分支、处理跨轮回状态与延迟披露，将求解出的必然命题回灌传播队列。

候选存在性必须由一段连贯合法历史支持。一个剧本的一条路径失败并不足以排除剧本；真实秘密动作不能代替未知变量。只比较当前盘面、按每条观察独立拼接不一致历史均不合格。

说明如何复用规则语义或验证约束编码与真实引擎一致，避免两套规则无约束漂移。提出候选见证的具体重放校验方式。

C. 加速路线比较

至少比较：规则传播加显式搜索／记忆化的基线；增量 CSP／SAT／SMT 或符号执行；一种分类、对称性、观察相关切片或抽象细化方法。BDD 可作为候选，但不为覆盖名词实现所有方法。

每个方法说明适用规模、成本、最坏情况、精确性、可解释性和工程复杂度。特别证明何时可以只运行某类的代表，区分当前查询等价与未来行为等价；合并时保留剧本和运行状态的关联。

推荐一个可验证的起点与备选路线。技术依据使用官方文档、原始论文或工具作者材料。可以参考主方案中引用的 Programming Z3，但不预先锁定它。

D. 预算、查询与理想实验完成契约

设计低成本传播、符号查询和显式枚举的调度。候选数量未知时考虑截断枚举、变量域与分支估计，不为决定是否枚举先做昂贵精确计数。阈值由基准测量确定，不虚构常数。

按主方案第 9 节给出实验前可固定的查询集合与完成契约，涵盖身份、规则、事件当事人、秘密牌资源及必要联合关系。说明有限查询目标的精确完成与保存完整联合约束之间的关系，不把所有单变量候选表误称为全部联合逻辑后果。

普通模式异步更新；理想实验在决策点等待登记目标精确完成。预算用尽、未知规则、证据矛盾等需要不同状态；未知不等于不可能，切换普通模式也不能保留理想样本标签。

E. 正确性案例与基准

至少覆盖以下场景，来源与假设须清楚标注：

  • 未收录但合法且符合公开设定的剧本必须保留；改变目录内容不改变推理结果。
  • 明确 8 人角色全集与仅当前在场 8 人产生不同约束；候选服从前者的完整人数限制。
  • 主人公成员共享已确认暗牌，剧作家未到揭示时点仍不知道牌面。
  • 接受／可选拒绝／强制拒绝，十周年拒绝不消耗次数，且不错误阻断后续合法发动。
  • 唯一密谋 +2 已知消耗后收窄暗牌；只有服务器知道时，主人公候选不应被额外删减。
  • 确定一个身份后，通过全局人数约束进一步收窄其他角色。
  • 同一剧本一条隐藏路径失败、另一条仍相容；相同当前盘面但历史信息不同；相同当前视图但未来行为不同。
  • 析取观察不被拆成多个独立成立的事实；自然语言不增加秘密原因。
  • 获知时点与命题有效时点不同；同时结算；窗口关闭后的缺席推理；事件发生但无现象；轮回结束披露与跨轮回知识。
  • 求解超时、未知规则和矛盾不被标为精确完成，理想实验门槛不被提前放行。

用小规模完整枚举作为参照，但初始集合仍从明确规则生成。与候选算法差分比较可行剧本、隐藏状态和目标命题；辅以独立手工例子，不能只让两个共享同一错误的实现互相验证。

基准报告变量规模、初始构造条件、隐藏分支、历史长度、耗时、内存、完成率和精确性；目录大小不代表初始解空间大小，单变量候选数也不代表联合解数。

4. 输出要求与工程边界

输出一份 HTML 算法设计文档：数据模型、伪代码、方案比较、推荐路线、预算实验、完成契约、验收判据和接口需求。保存到临时目录并返回绝对路径；交付引用本方案，避免重复抄写已确认设计。

必要时可在临时目录做小原型，附源码、命令、输入参数和原始结果。没有运行则明确标为设计，不能声称性能达标。最终报告区分已确认领域决定、实测证据与可修订的工程建议。

本阶段不修改仓库文件，不创建 Issue／PR，不推送或部署；facts/ 只读，不恢复 archive/ 的旧引擎。需要将成果正式纳入工程时，报告可独立实施的后续工作。对尚待校对的内容规则显式标记支持边界，不自行编造。

主状态机方案与本算法任务均不包含对手必然最优的假设，不保证唯一剧本，也不把“理想推理”扩大为全知或完整最优行动策略。GUI 开关作为后续接口需求保留。
