2. 总体模型与处理链

公开规则 R + 权威状态 S + 行动 A
                ↓ 规则结算
        下一权威状态 S′ + 内部结算记录
                ↓ 按阵营、时点和披露规则投影
           结构化观察批次 O
                ├─ 标准自然语言呈现 → 玩家
                └─ 追加到该阵营历史 H
                              ↓
                  约束更新与两种删减机制
                              ↓
                     联合解空间 K + 推论

两个主要观察者是主人公阵营 P 和剧作家 M。服务端权威状态不等于任一方的视图。主人公共享成员信息，不意味着获得剧作家的秘密；剧作家知道剧本，也不意味着提前知道主人公的暗置牌面。

规则引擎决定实际发生什么；观察投影决定获准披露什么；推理模块决定这些信息逻辑上排除了什么。推理结果不改变真实身份、不代替游戏胜负判断，也不自动触发要求“正式公开”的规则效果。

3. 权威状态有哪些内容

概念上，权威状态包括固定配置与运行状态。观察历史另外保留，知识可由规则与历史重建。

层次 内容 关键约束
规则配置 十周年语义、模组、角色卡／身份／牌／事件定义、内容版本 重放与推理绑定版本；公开规则定义与秘密选用的规则组合分开
剧本设定 公开信息、选用规则、角色全集与初始身份、事件日程及当事人、登场安排、特殊设定 公开与秘密字段明确区分；目录编号不是候选筛选依据
当前盘面 登场状态、存活状态、位置、当前身份、能力与特性、关系、角色和区域指示物、持续效果 角色卡、初始身份、当前身份、当前能力分开；持续效果有失效条件
行动资源 各套手牌及牌实例、可用／暗置／揭示／弃置状态、目标、每轮限制、能力剩余次数 记录实际行动者和资源归属；共享视野不取消资源限制
流程 轮回、日、阶段、阶段内步骤、待选择者、待结算效果、同时组和延迟处理 不只是“第几天”；相同盘面处于不同选择点时，合法输入不同
跨轮回记录 正式身份公开、跨轮回效果、下轮准备标记 盘面复原不清空观察历史；推理确定不等于正式公开
游戏结果 当前轮回结束原因、结束处理进度、下一轮／最终决战、最终胜负 触发结束后，仍须处理规则要求的结算与披露

未知信息不是从权威状态中删除，而是由各方视图控制访问。不能用单个“不知道”的值覆盖服务端实际身份。

规则推进到稳定的选择点再等待行动；无须选择的强制处理可继续执行。同一时点要求同时结算的效果使用共同的规则前提与结算组，不能把遍历顺序当成规则顺序。轮回结束后先完成必要处理与披露，再初始化下一轮。

4. 行动、宣告与次数消耗

**行动是选择，不是真值陈述。**它携带行动者、选择类型、对象与参数。规则引擎确认的行动可以产生“某选择已作出”的观察，但原始行动输入不直接作为所有玩家都能读到的观察。

建议处理阶段：

检查是否可宣告 → 确认并记录宣告 → 处理接受／拒绝
                                  ├─ 拒绝：记录拒绝，不消耗本次次数
                                  └─ 接受：按能力条文处理次数与效果

十周年拒绝语义由本会话设计者明确提供，不再列为待确认。它没有规定所有能力必须统一在哪个接受子步骤扣次数；其余细分时机仍按具体规则定义。

宣告记录、拒绝记录、次数消耗是不同事实。拒绝不增加剩余次数，不等于恢复资源；只是该次拒绝不消耗。它也不妨碍剧作家之后在相应合法时机发动。

已确认的自身选择会生成阵营可见的确认观察。未提交的心理意图、鼠标拖拽草稿、网络重试不是游戏历史。主人公阵营完整共享已确认的选择；合作编辑草稿是后续 GUI 细节。

“无视友好”影响宣告后的处理，不能依据真实身份提前隐藏主人公本来可宣告的能力。可拒绝身份也能接受，因此观察到接受不能排除所有可拒绝身份。

5. 结构化观察与逻辑语句

5.1 语句内容与观察上下文

观察由获准披露的逻辑内容以及解释该内容所需的上下文组成。它是一条直接证据，不是自由文本日志。以下字段名是接口草案：

{
  "id": "p:42",
  "audience": "protagonists",
  "learnedAt": {"loop": 1, "day": 2, "phase": "protagonist_ability", "window": "w7"},
  "disclosureBatch": "p:b12",
  "statement": {
    "kind": "atom",
    "predicate": "ability_attempt_refused",
    "arguments": {"attempt": "a17", "character": "doctor"},
    "at": {"loop": 1, "day": 2, "phase": "protagonist_ability"}
  }
}

learnedAt 表示何时获知；语句的 at 或有效范围表示它谈论何时。复合语句的子命题必要时分别限定时间。初始身份与当前身份使用不同语义的谓词，不能仅靠默认时间猜测。

观测标识与可见对象引用必须足以关联证据，但不能泄露隐藏实体、内部事件数量或真实原因。披露批次表示对外可见的交付单元；规则的同时结算关系另行表达，不能以同批发送就断言同时发生。引用只能关联规则允许玩家关联的对象与动作。

5.2 有限逻辑语言

建议最小表达结构：

Statement = Atom(predicate, typedArguments, timeScope)
          | Not(Statement)
          | And(Statement...)
          | Or(Statement...)
          | Compare(observableTerm, operator, value)
          | Cardinality(boundedDomain, predicate, operator, integer)

对象类型至少覆盖角色、区域、身份、规则、能力、行动牌、行动尝试和逻辑时点。注册谓词定义参数类型、精确语义、允许出现的时间范围和自然语言模板。普通布尔、比较、计数语义固定；有限集合的成员范围必须明确，避免把“所有角色”误读为“此刻仍存活的角色”。

第一版不允许自由嵌入任意程序，也不要求支持无界量词。新增模组关系必须补全语义、披露与呈现支持，不能以未解释的字符串继续声称精确推理。

5.3 原子性约束披露，不限制表达能力

“医生位于医院”是一条简单观察。“A 或 B 至少一人是关键人物”也可以是一个不可独立拆分的披露单元；它不能被改写为两条都成立的身份观察。此例是语言能力示例，不声明某个已支持模组一定存在此能力。

能安全独立表达的多个事实可以拆成多条观察。是否允许拆分还取决于披露时点与关联；语义归一化不能凭空增加事实、因果或秘密来源。最小披露单元与同时结算组是两个概念。

5.4 建议的首批谓词族

领域 示例语义 使用约束
初始化 角色全集为给定集合、轮回／天数上限、公开日程 明确全集、上限、当前在场数量的区别
盘面 位置、登场／存活状态、某类指示物数量 只陈述该时点允许观察的状态
行动 某阵营已放置一张牌、某次能力已宣告、某次宣告被拒绝 暗置位置与秘密牌面是不同披露
牌资源 某牌面已知、某次限次资源已消耗 只凭合法披露使用，不能读取对手真实手牌补齐
身份与规则 初始身份、当前身份、规则选用情况 只有规则直接披露时进入历史；推理结果留在知识层
剧本事件 事件发生、允许披露的效果 “发生但无现象”不等于“未发生”
流程与披露 阶段／窗口结束、规则允许公开的同时关系 完整性范围来自公开契约，不发布秘密触发数量

这是可扩展的起点，不是全部模组已经结构化完成的声明。

6. 自然语言、双方视图与历史

6.1 标准自然语言呈现

结构化语句类型检查
→ 解析该观察者有权使用的对象名称和时间表达
→ 按谓词／逻辑运算模板组合
→ 输出可追溯到原观察的自然语言

例如 ability_attempt_refused(a17, doctor) 呈现为“医生的这次友好能力宣告被拒绝”。不能补上“因为他是邪教徒”，也不能把析取写成确定身份。历史回放中的过去事实必须显式保留时间含义。

多条观察可以组织成易读段落，但保留逐条展开与标识对应。推论以独立样式呈现并附依据；不把推论混进直接观察句子。逻辑内容是依据，中文或其他语言只负责表达，推理程序无需把自然语言反向解析回来。

6.2 完全共享的主人公视野

主人公阵营只有一份知识视角：成员各自获准知道的信息、本阵营已确认的选择与暗置牌面都共享。无需维护阵营内部禁言造成的不同知识状态。

这不取消席位、队长、行动顺序、手牌资源或合法目标限制；这些属于真实规则状态。剧作家获得自己的完整剧本信息和自己已确认的选择，但只在规则允许时看见主人公暗牌。

界面按钮、报错、日志、引用标识及公告顺序也属于信息渠道。视图接口及错误提示的输出只由该方合法信息决定；不能在普通界面旁夹带全知调试字段。

6.3 历史与观察窗口

历史统一包含初始化、自身选择确认和后续披露。各方观察历史不同；服务端内部结算记录不是玩家历史。

窗口公开结束后，只对规则保证完整披露的事实种类，才能从未出现的观察推导否定。结论是有依据的推论，不追加为伪装成直接披露的新观察。没有结束标记、没有完整性承诺或只是网络延迟时，缺席不构成否定证据。

同时效果先按规则处理，再原子提交必要的观察批次；历史保留稳定展示顺序和合法可知的同时关系。不得把内部任意排列或秘密结算步骤暴露为额外证据。

7. 初始解空间与完整历史兼容性

7.1 剧本目录不是信息，公开设定是约束

设 R 为公开规则版本及模组定义，P 为剧本公开信息。初始候选剧本集合为：

Θ₀ = { θ | θ 满足 R 的合法剧本构造规则，并满足全部公开设定 P }

P 通过初始化观察进入主人公历史；不再维护一份可能与历史矛盾的独立公开真相。

实际剧本可以来自目录、人工编写或生成器，但目录的收录状态、编号和样例分布均不提供候选筛选或先验概率。规则允许、公开信息也允许的剧本，即使从未被收录，也必须保留为可能。

**8 名角色例子：**如果公开设定明确角色全集只有 8 名，候选必须符合这份名单或数量约束，含第 9 名角色的剧本被排除。这与“某一时刻版图上可见 8 名角色”是不同语义；后者不能自行升级成对尚未登场角色的全集声明。语句必须准确表达公开信息到底约束了什么。

除了角色名单，公开模组、轮回与天数、公开日程、特殊公开条件等也约束初始空间。不能为了减少计算量擅自增加未公开的作者偏好或目录条件。

7.2 剧本与动态秘密共同建模

令 θ 为初始剧本，xₜ 为当前隐藏运行状态，Hₜ 为该观察者截至此时的完整观察历史：

Kₜ = { (θ, xₜ) |
       θ ∈ Θ₀，且存在一段合法历史，
       其完整可见记录与 Hₜ 一致，最终隐藏状态为 xₜ }

秘密行动、可选能力、秘密目标等作为存在性选择。已公开动作以及本阵营已确认的选择则固定为已知约束。不能用服务端真实秘密选择替代所有候选世界的可能选择，也不能假定剧作家必定采取最优策略。

保留一个剧本只需有一条连贯的合法隐藏历史能解释全部观察；排除它必须证明没有任何这样的历史。只匹配最终盘面不够，也不能拼接彼此不相容的过去解释。

剧本候选与当前隐藏状态候选是 K 的两种投影；底层保存联合关系。单独列出每个角色的候选身份会丢失“恰好一人是关键人物”等关联。

新增真实证据只能缩小固定初始剧本的候选范围；动态隐藏状态则会随新的秘密选择或轮回重置出现新可能。盘面重置不清空知识。初始身份、当前身份、规则组合和完整剧本的唯一性分别查询，不保证全部秘密最终都能唯一识别。

8. 两种删减机制与计算策略

8.1 信息点驱动的传播

信息点指有来源的命题。直接观察、规则和推论可以作为推理依据；用户猜测另存为假设，不直接收紧真实解空间。

新观察 → 约束／命题 → 工作队列
       → 受影响规则、数量约束与互斥约束
       → 候选删减或新推论 → 再次入队 → 固定点

记录每个推论依赖的规则版本、观察和前提，去重避免循环自证。在有限域上，单个历史前缀的单调删减可作为传播终止基础。传播固定点不等于已经得到全部逻辑后果。

8.2 完整兼容性检查

兼容性模块检查一个候选或命题是否存在合法见证历史。可用增量约束求解或符号执行表达多个世界，不要求首先生成全部候选剧本。证明的新事实回灌传播队列，传播结果也简化后续求解。

两种方法必须共享规则语义，或由独立差分测试证明一致；不能随意手写两套游戏规则。具体选择由算法任务研究：共享规则表示的不同执行后端，或约束编码配合真实引擎见证重放。

8.3 加速与预算建议

方法 主要收益 必须保留的边界
域传播、数量／互斥约束 低成本收窄候选，解释直接 不完备，固定点不是精确穷尽
增量 CSP／SAT／SMT 复用历史前缀，按查询寻找反例 编码覆盖全部合法隐藏选择，不能只模拟真实路径
显式搜索与记忆化 小空间精确参照，复用重复工作 不能为省时丢弃影响未来的状态和剧本关联
对称性与分类 合并真正等价的候选处理 相同当前视图不足以证明永久等价
抽象与逐步细化 先保留与观察相关的细节 抽象应覆盖全部真实可能；抽象见证可能需要进一步核验

某一分类只对当前查询等价时，可以批量处理该查询，但须保留组内未来可能不同的成员。永久状态合并需要证明相关动作和未来观察行为等价，并保留必要的剧本关联。

所有新观察先做低成本传播。符号查询可以从早期使用；显式枚举则由剩余规模、隐藏分支、历史长度、实测成本和资源预算决定。可用截断枚举判断是否超过门槛，避免为决定是否枚举先做完整计数。具体阈值不在此虚构。

初步技术参考：Programming Z3 包含增量求解与模型检查等机制；这不代表项目已经选用 Z3 或验证性能。

8.4 查询结果与矛盾处理

候选查询返回“已证明可能（有合法见证）／已证明不可能／尚未判定”。只有基础知识一致时，才能通过否定命题无解来证明必然结论。

若已知证据与规则整体无解，报告知识不一致并定位冲突依据，不能利用矛盾推出任意身份。求解超时、规则未支持、观察矛盾分别报告；采样失败和没找到见证不等于不可能。

9. 普通模式与理想推理实验

**普通模式：**规则结算独立于求解器；玩家可以继续行动，知识异步更新。每项结果绑定规则版本、观察历史前缀和完成状态，避免把旧结果显示成最新结论。

**理想推理实验：**在下一个玩家决策点，固定当前历史前缀与事先声明的研究查询集合，等待这些目标精确完成再允许输入。真实规则仍照常推进到该决策点，不增加游戏内特殊能力。

建议首批研究查询覆盖角色初始／当前身份、所选规则、事件当事人、暗牌与资源的可行取值，以及预先登记的联合关系问题。它们是工程建议；算法任务应给出完整查询契约，并在实验开始前固定，不能事后缩小查询集合来宣布完成。

到达决策点 → 固定历史版本与查询目标
            ├─ 全部目标精确完成 → 开放下一次玩家选择
            ├─ 仍在求解 → 等待
            └─ 超时／不支持／矛盾 → 暂停或标记实验未完成

理想标签只保证登记目标的精确完成，不宣称已经列出所有等价命题，也不等于全知或最优行动策略。若改为继续普通游玩，后续记录不能继续冒充该条件下的理想样本。

GUI 可开关显示候选、确定结论、依据和进度。关闭显示不更改披露规则、资源或胜负条件；研究中的模式和完成门槛另行记录。

10. 四个贯穿示例

示例一：8 名角色的公开剧本

初始化观察声明角色全集为 c1 至 c8，并披露相应日程与上限。Θ₀ 排除任何违反这些公开条件的剧本；未被目录收录但满足全部条件的身份与规则组合仍保留。输出“剩余候选”的依据是合法构造规则与公开信息，而非样例目录。

示例二：阵营共享与密谋 +2

主人公 P1 的暗置选择经确认后，其牌面与目标立即进入主人公共享历史。剧作家此时只得到规则允许的放置观察，不能从主人公共享界面读取牌面。

另一个时点，若主人公已合法获知剧作家的唯一密谋 +2 本轮已经消耗，且规则没有恢复／复制途径，则当前未揭示牌位不可能再是该牌。仅服务端知道消耗时不能用来筛选主人公的候选；角色、牌位及剩余数量之间的联合约束必须保留。

示例三：好感能力被拒绝

主人公宣告医生的能力。规则确认宣告，随后剧作家拒绝；主人公历史记录宣告与拒绝。依据十周年规则，推理得出这次拒绝不消耗次数，结论留在知识层。

在没有其他规则干预的简化条件下，拒绝排除不能拒绝的身份，保留可以拒绝和必须拒绝的身份。接受则排除必须拒绝的身份，但不排除可以拒绝的身份。涉及获得特性或身份变化时，将那些可能性一并求解。剧作家后续合法发动不受此次拒绝错误封锁。

示例四：同时结算、延迟披露与窗口结束

两项按规则同时发生的死亡，内部共同结算后生成获准披露的观察。即使历史排列为“先 A 后 B”，推理也依据同时关系，不把第一项结果反过来取消第二项的触发前提。

轮回结束时，如果规则要求公开某个身份，新的观察以结束时为获知时间，并准确注明它声明的是初始身份还是当时身份。它更新现在的知识，不改写过去的知情状态；正式公开标记可参与下一轮规则。

如果某公开窗口已经结束，且规则保证某类事实必定完整披露，该类公告的缺席才可生成否定推论。事件发生但没有现象时仍需保留其应公开的发生事实，不能当成事件未发生。

11. 接口、依赖与验收边界

11.1 建议的模块接口

transition(authoritativeState, action)
  -> nextState + internalResolution + nextDecision

disclose(observer, before, after, internalResolution)
  -> permittedObservationBatches

render(observation, permittedNames, locale)
  -> naturalLanguage + sourceObservationReferences

append(history, batches)
  -> newHistoryVersion

updateKnowledge(previousKnowledge, publicRules, newHistory)
  -> knowledge + progress

query(knowledge, proposition, budget)
  -> possible(witness) | impossible(evidence) | unknown(progress)

整体知识不一致作为独立错误状态处理。观察可由前后状态与完整结算上下文组合产生，不要求每个内部变化一对一对外发布。View 使用公开投影与历史，推理辅助叠加层另读知识结果。

普通模式的规则引擎不等待求解器；理想实验门槛由外层实验控制逻辑管理。连接、重连、并发版本和命令去重属于应用会话层，不作为隐藏身份变量。

11.2 必须验证的性质

  1. 所有合法真实对局的世界始终留在对应观察者的候选空间中。
  2. 相同规则、公开信息及合法观察历史产生语义相同的知识，不受真实秘密影响。
  3. 目录有无某剧本不影响推理；明确 8 人全集时排除 9 人剧本。
  4. 主人公成员获得同一共享历史；对剧作家的暗牌保密仍然成立。
  5. 行动、直接观察、推论分别处理；宣告不等于成功，推论不等于正式公开。
  6. 自然语言忠实呈现复合语句与时间，不增加秘密原因；观察与原句可追溯。
  7. 一条隐藏路径失败不排除仍有其他合法路径的剧本；当前视图相同不自动合并历史。
  8. 同时结算与延迟披露保持规则语义；缺席否定只在关闭且完整的范围内成立。
  9. 小规模全枚举与精确算法的剧本、隐藏状态及目标查询一致；手工语义例子提供独立参照。
  10. 超时、规则未支持、矛盾及旧历史结果不能被标为精确完成；理想实验只在登记目标完成后放行。

GUI 自动检查与人工验收分别记录。当前没有引擎实现或算法基准结果，现有 pnpm check 只验证工程配置。
