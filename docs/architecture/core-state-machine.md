# 核心状态机设计

状态：草案  
最近更新：2026-06-21

## 目标

规则核心负责表达游戏真实状态、校验玩家意图、执行结算并产生日志。它不依赖浏览器 DOM、网络连接或具体 UI。

当前实现位于 `code/web/core/`：

- `data.mjs`：静态定义，包括剧本、角色、身份、行动牌、区域。
- `engine.mjs`：状态机与结算函数。
- `rules.test.mjs`：核心规则测试。

## 状态流

核心采用单向状态流：

```text
Command -> validate -> resolve -> GameEvent[] -> GameState -> projectView
```

- `Command` 是玩家意图，例如暗置行动牌、使用剧作家能力、提交最终猜测。
- `validate` 拒绝非法意图，例如在死亡角色上放牌、同阵营重复选择目标。
- `resolve` 修改状态，例如移动角色、增减指示物、触发事件。
- `GameEvent` 记录发生过什么，同时带有可见性。
- `projectView` 将完整状态投影成剧作家视图或主人公视图。

UI 应尽量只展示核心给出的合法选项，但核心仍必须保留防御式校验，以便未来联机时拒绝伪造请求。

## 角色卡公开信息

角色卡公开信息来自静态角色定义，并会投影给所有玩家。它包括：

- 不安限度。
- 友好限度，也就是该角色最高友好能力门槛。
- 公开友好能力列表，每项包含所需友好度、时机、是否每轮限 1 次和效果摘要。
- 公开角色特性，例如禁行区域。
- 角色标签，用于和规则或其它角色能力联动。

隐藏身份能力不属于公开角色卡信息。它由角色当前 `roleId` 决定，只能出现在剧作家视图或已公开身份的主人公视图中。

友好能力解锁规则：

- 技能上方粉红爱心数量表示解锁所需好感度。
- 达到较高好感度时，较低门槛技能也同时可用。
- 每天发动技能时，不是在已解锁技能中选择一个，而是所有可用技能都可以发动。
- 标注每轮限一次的技能在整个轮回中只能使用一次；未标注者默认每天可发动一次。
- 技能模型需要支持例外使用方，例如医生在身份具有无视友好特性时，可由剧作家在剧作家能力阶段使用。

## 阶段

当前第一版阶段顺序：

1. `dawn`：黎明阶段。当前第一版没有黎明效果，只提供阶段占位和推进入口。
2. `mastermind_action`：剧作家暗置 3 张行动牌。
3. `protagonist_action`：主人公方暗置 3 张行动牌。玩家人数不影响行动牌总数。
4. `mastermind_ability`：剧作家发动已实现的隐藏身份能力或符合例外条件的友好能力。
5. `protagonist_ability`：主人公友好能力阶段。主人公逐项选择已解锁且有可选对象的能力；每宣告一项能力后，若角色身份需要剧作家判断是否无视友好，则进入待审批状态，审批和结算完成后才选择下一项能力。
6. `incident`：检查当日预定事件。
7. `end_of_day`：检查回合结束能力，例如杀人狂、杀手。
8. `loop_end` / `final_guess` / `finished`：轮回失败、最终决战或游戏结束。

各阶段的入口、允许命令和详细结算规则见 `docs/architecture/phase-resolution.md`。

## 合法选项

核心提供合法选项 helper：

- `actionLimit(state, side)`：当前阵营本阶段行动牌上限。
- `placedActionCount(state, side)`：当前阵营已暗置数量。
- `listLegalTargets(state, side, cardId)`：当前行动牌可选择的目标。
- `availableMastermindAbilities(state)`：当前可发动的剧作家能力项。
- `availableMastermindAbilityActors(state)`：当前可发动剧作家能力的角色。
- `listMastermindAbilityTargets(state, actorId, abilityId)`：指定剧作家能力项的合法目标。
- `availableProtagonistAbilities(state)`：当前满足友好门槛、未用过且存在结构性可选对象的主人公能力。
- `listProtagonistAbilityTargets(state, actorId, skillId)`：指定主人公能力的结构性合法对象。

这些 helper 会过滤：

- 死亡角色。
- 同阵营已经放置行动牌的角色或版图。
- 已经在本日使用过能力的角色。
- 当前没有合法目标的能力角色。

主人公能力的候选过滤只检查“能力能否选择对象”，不检查对象当前是否会产生实际变化。例如男学生与女学生在同一区域，即使女学生身上没有不安，男学生移除学生不安的能力仍然可以发动；结算时才发现没有指示物可移除并记录无变化。

主人公能力审批规则：

- 没有无视友好特性的身份：能力自动接受并结算。
- 强制无视友好的身份：能力自动拒绝。
- 可无视友好的身份：进入 `pendingDecision`，由剧作家接受或拒绝。
- 审批是逐能力进行的；不能先批量提交多项能力和对象再统一审批。

## 行动牌与弃牌堆

主人公方不是共享一副行动牌，而是拥有绿、红、蓝三副行动牌。当前原型把主人公行动阶段建模为三个彩色行动位：

- 每个行动位每阶段最多暗置 1 张行动牌。
- UI 按绿、红、蓝固定顺序推进主人公行动位。
- 每轮限 1 次的行动牌按副牌分别追踪。
- 因此绿、红、蓝三副牌的 `友好 +2` 若都尚未进入弃牌堆，同一回合可以打出三张 `友好 +2`。
- 每轮限 1 次的行动牌在揭示结算后进入本轮弃牌堆；剧作家和主人公视图都会显示弃牌堆，并保留主人公行动牌颜色。
- 行动牌揭示前，牌名仍按视图隐藏，但目标位置对双方公开，并在角色或版图上显示暗置标记。

## 视图投影

`projectView(state, viewer)` 用于生成不同玩家看到的状态：

- 剧作家视图显示完整 closed script，包括角色身份、采用规则、事件当事人和隐藏原因日志。
- 主人公视图隐藏未公开身份、采用规则真相、事件当事人和隐藏原因日志。

后续联机版本应让服务端持有完整 `GameState`，只把对应的投影视图发送给各客户端。

## 本地分屏视图

浏览器原型支持把剧作家和主人公拆到不同页面：

- `/`：双视图调试页，同时显示剧作家视图和主人公视图。
- `/?view=mastermind`：只显示剧作家投影视图，并提供剧作家相关控制。
- `/?view=protagonists`：只显示主人公投影视图，并提供主人公相关控制。

这些页面使用同源 `localStorage` 和 `BroadcastChannel` 同步同一份本地 `GameState`，效果类似 Marp 演讲者视图的双页面联动。任一页面执行合法操作后，会广播新状态，其他页面重新按自己的 viewer 投影。

注意：这是本地原型同步方式，不是安全边界。因为同源页面共享浏览器存储，隐藏信息在技术上仍在本机浏览器里。正式联机版必须由服务端保存完整状态，只向不同客户端发送对应的 `projectView` 结果。

## 第一版边界

已实现：

- 初学者剧本。
- 当前登场角色的公开友好能力和友好限度投影。
- 友好能力使用方、使用频率和例外条件的静态建模。
- 行动牌暗置与结算。
- 移动、友好、不安、密谋、禁止类基础结算。
- 剧作家阶段的主谋、传谣人能力，以及医生在无视友好身份特性下由剧作家使用友好能力的例外。
- 自杀事件。
- 杀人狂同时结算、杀手、关键人物死亡失败。
- 轮回重置与最终决战。

暂未实现：

- 完整友好能力库。
- 多名主人公的队长分派 UI。
- 所有惨剧模块、身份、事件。
- 需要中途选择目标的复杂结算队列。
