接口输入输出与边界
MastermindPort暗置行动牌、身份／规则能力、指定效果选择、友好拒绝。公开盘面、剧本秘密、自己的暗牌和合法决策；不返回主人公暗牌及 LL 他人秘密编号。
ProtagonistPort按顺序提交自己的行动牌；队长提交普通团队决策；个人专属选择由本人提交。主人公共享游戏观察、己方暗牌知识、公开决策。LL 秘密编号仅本人可见。
Trusted host完整剧本、LL 明确记录的洗牌结果、执行预算。快照、继续执行、诊断；不把全知状态直接发送到玩家端。

每次命令校验当前决策、角色与版本。重复 ID 和相同内容不会重复执行；相同 ID 配不同内容被拒绝。预算耗尽返回 paused，保留可继续执行的状态。

讨论与不讨论模式只影响讨论窗口；普通决策和个人例外仍按规则归属。相同游戏观察不会因讨论开关改变参考验证结果。LL 的讨论开关沿用项目明确要求的统一交互策略，个人编号与选择权仍保留。

展开完整接入示例

示例使用随报告提供的完整合法 FS 输入，可检查双方端口和重放得到一致胜负。该示例不是决策模型。

// 仓库根层 TypeScript 文件的导入方式；用 pnpm exec tsx 文件名.ts 运行。
import { readFileSync } from 'node:fs';
import { compileOfficial } from './packages/content/src/official/index.js';
import { createSession, replay } from './packages/engine/src/index.js';
import type { GameSetup, Choice, Actor } from './packages/contracts/src/index.js';

const sample: { setup: GameSetup; trace: { actor: Actor; choice: Choice }[] } =
  JSON.parse(readFileSync('./products/engine/example-replay.json', 'utf8'));
const pack = compileOfficial(sample.setup.module, sample.setup.anniversary);
const session = createSession(pack, sample.setup);
if (session.status !== 'ready') throw new Error(JSON.stringify(session.diagnostics));

// 宿主按既有样本选出合法动作；实际玩家只能持有自己的端口。
for (const [index, action] of sample.trace.entries()) {
  const port = action.actor === 'mastermind'
    ? session.mastermind : session.protagonists[action.actor];
  const view = port.view();
  if (!view.decision) throw new Error('尚未轮到此玩家');
  // 新对局按 decision.options 选择；出牌读取 decision.cardPlacement。
  const result = port.submit({
    id: 'sample-' + index, expectedRevision: view.revision,
    decisionId: view.decision.id, choice: action.choice,
  });
  if (result.status !== 'ok') throw new Error(result.status);
}
console.log(session.protagonists.p0.view().winner);
// 重放接口用 choices 字段；导出文件的字段名为 trace。
const checked = replay(pack, { setup: sample.setup, choices: sample.trace });
console.log(checked.status);

已落实的特殊结算语义

  • Q1：同批死亡请求是多重集合。从者两项替代加自身一项共三项请求，一枚护卫只取消一项，最终实际死亡只登记一次。
  • Q2：结束要求锁定后完成已成立批次、死亡触发和已到时点的完成后处理。未开始的“随后”步骤中断；被截断的来源不登记完成。
  • Q3：轮回结束处理全部完成后保存前轮快照，再在下轮复原与登场之后应用跨轮效果；第一轮没有虚构的上一轮。
  • 事件发生与仅调用事件效果分开。AI 调用不增加发生次数，也不因旧发生标志触发“本局首次发生”。
  • 原始指示物与有效值分开；身份名称与获得身份能力分开；AHR 表里身份成对配置；LL 标志跨轮保留且特殊胜利仅在规定阶段检查。

自然语言来源不直接执行。规则包使用有限的条件、目标选择、效果和步骤结构；核心操作由内核实现。来源快照哈希变化会使来源检查失败，需要重新核对翻译。

为解空间预留的一致性边界

参考验证器以联合剧本假设为单位搜索完整合法行动轨迹，调用与实际对局完全相同的 initialize／advance 和观察记录。一个配置有一条合法解释就可证明可能；搜索被预算截断时返回 unknown。

目前接口只对调用者明确提供的有限候选域作结论；不会把几个示例剧本当成全体合法剧本。它是核对引擎语义的参照，不是完整实时解空间系统。尚未实现自动全域配置生成、持久化的全部相容状态前沿、增量约束求解、精确计数或新增析取关系提取。

支持隔离假设、历史追加版本检查和见证重放。讨论模式不进入观察内容；不使用真实对局的秘密动作剪掉其他合法解释。LL 的个人秘密需要调用方明确采用相应观察范围，当前参考入口使用主人公共享观察。
